## Why this matters

Server data is not the same as local UI state: it is shared, async, stale-able, and owned by the backend. Hand-rolling useEffect + useState for every endpoint recreates caching, deduping, and race handling poorly.

<Callout type="mental-model">
  A query is a declarative dependency on async data keyed by a stable queryKey. status describes the data; fetchStatus describes the in-flight request.
</Callout>

## Minimal useQuery

Provide QueryClientProvider once. Treat queryKey as part of your public API for invalidation.

```tsx
import { useQuery } from '@tanstack/react-query';

type Topic = { id: string; title: string };

export function TopicTitle({ id }: { id: string }) {
  const { status, data, error, isFetching } = useQuery({
    queryKey: ['topic', id],
    queryFn: async (): Promise<Topic> => {
      const res = await fetch(`/api/topics/${id}`);
      if (!res.ok) throw new Error('Failed to load topic');
      return res.json();
    },
  });

  if (status === 'pending') return <p>Loading…</p>;
  if (status === 'error') return <p>{(error as Error).message}</p>;
  return (
    <h1>
      {data.title} {isFetching ? '…' : ''}
    </h1>
  );
}
```

## Common mistakes

- **Putting server lists in global client stores** — You reimplement cache + freshness poorly.
- **Unstable query keys** — New array/object identity every render breaks caching.
- **Ignoring mutations/invalidation** — UI shows stale data after writes.
