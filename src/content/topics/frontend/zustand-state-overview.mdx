## Why this matters

Prop drilling and mega-Context providers make features brittle. Small external stores (Zustand) update only subscribed components—useful for client UI state, not a replacement for server cache.

## Mental model

<Callout type="mental-model">
  Server state → TanStack Query. Form/ephemeral UI → local state. Cross-cutting client UI (sidebar, wizard step, feature flags in memory) → Zustand/Context. Prefer the smallest tool that works.
</Callout>

## How it works

Create a store with `create`, select slices with selectors to avoid rerendering the world, and keep stores domain-sized.

```ts
import { create } from 'zustand';

type UiState = {
  sidebarOpen: boolean;
  toggleSidebar: () => void;
};

export const useUiStore = create<UiState>((set) => ({
  sidebarOpen: false,
  toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
}));

// In a component: const open = useUiStore((s) => s.sidebarOpen);
```

## Common mistakes

- **Mirroring all API data into Zustand** — Duplicates TanStack Query / RSC.
- **Selecting the whole store** — Causes broad rerenders; select fields.
- **Giant god-store** — Split by domain.
