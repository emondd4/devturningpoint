## Why this matters

Broken forms exclude users and create support tickets. Accessibility is correctness: every control needs a name, errors need association, and focus must be predictable.

<Callout type="mental-model">
  Prefer native label/for and required/aria-invalid before custom ARIA. If you invent a widget, you inherit the keyboard and announcement contract.
</Callout>

## Pattern: label + described error

Associate help and error text with aria-describedby; move focus to the first invalid field on submit failure.

```tsx
export function EmailField({
  error,
}: {
  error?: string;
}) {
  const describedBy = error ? 'email-error' : 'email-hint';
  return (
    <div>
      <label htmlFor="email">Email</label>
      <input
        id="email"
        name="email"
        type="email"
        autoComplete="email"
        aria-invalid={Boolean(error)}
        aria-describedby={describedBy}
      />
      <p id="email-hint">We only use this for account recovery.</p>
      {error ? (
        <p id="email-error" role="alert">
          {error}
        </p>
      ) : null}
    </div>
  );
}
```

## Common mistakes

- **Placeholder as label** — Disappears on type; not a durable accessible name.
- **Color-only errors** — Fail WCAG; pair with text and aria-invalid.
- **Custom selects without keyboard** — Must support arrow keys and Escape.
