## Why this matters

A blank shell with client-only content can rank poorly or share badly. Search engines improved at JS, but reliable indexing still favors meaningful HTML, titles, and links.

## Mental model

<Callout type="mental-model">
  Crawlers discover URLs via links/sitemaps, then need usable content and metadata. SSR/SSG/RSC reduce “empty shell” risk. Client routers must still expose real URLs.
</Callout>

## How it works

Use semantic headings, unique titles/descriptions, indexable links (`<a href>`), and framework metadata APIs. Prefer server-rendered primary content for public pages.

```tsx
// Next.js App Router metadata
export const metadata = {
  title: 'React rendering — Dev Turning Point',
  description: 'What causes a React component to render, with interview angles.',
};

export default function Page() {
  return (
    <article>
      <h1>What causes a React render?</h1>
      <p>Initial mount and state updates are the primary triggers.</p>
    </article>
  );
}
```

## Common mistakes

- **Only button onClick navigation** — Crawlers and users need real links.
- **Identical titles across pages** — Hurts sniping in search results.
- **Blocking content behind auth for marketing pages** — Public content should be in HTML.

## Interview angle

<Callout type="interview">
  Why might a client-only SPA fail SEO expectations, and what does SSR/SSG change for crawlers?
</Callout>

## Practice checklist

- [ ] Audit title/h1 on two routes
- [ ] Ensure primary nav uses anchors
- [ ] Add metadata for one page
