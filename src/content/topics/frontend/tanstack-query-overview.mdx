## Why this matters

Ad-hoc `useEffect` + `useState` for every GET breeds race conditions, duplicate requests, and no shared cache. TanStack Query treats server data as a first-class cache with lifecycle.

## Mental model

<Callout type="mental-model">
  Query keys identify cached data. Stale-while-revalidate keeps UI fast while refreshing. Mutations update server then invalidate/refetch related queries.
</Callout>

## How it works

Wrap the app in QueryClientProvider. Use `useQuery` for reads and `useMutation` + `invalidateQueries` for writes. Keep keys stable and hierarchical.

```tsx
const topicsQuery = useQuery({
  queryKey: ['topics', { track: 'frontend' }],
  queryFn: () => getJson('/api/topics?track=frontend'),
  staleTime: 30_000,
});

const createTopic = useMutation({
  mutationFn: (body: { id: string }) =>
    fetch('/api/topics', { method: 'POST', body: JSON.stringify(body) }),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['topics'] }),
});
```

## Common mistakes

- **Putting server cache into Redux/Zustand by default** — Use Query for server state; local UI state elsewhere.
- **Unstable query keys** — New object identity every render busts the cache.
- **Ignoring error/loading states** — Ship explicit UI for each.
