## What is this?

A render should be a **pure calculation**: same inputs ⇒ same JSX, and no mutating external data during the calculation.

## Why it exists

React may render components more than once (especially in Strict Mode development checks). Impure renders cause duplicated side effects and UI that depends on call count.

## Mental model

<Callout type="mental-model">
  During render: calculate. After commit: synchronize with the world (effects), respond to events (handlers).
</Callout>

## Impure vs pure

```tsx
// Impure: mutates a shared object during render
let shared = { clicks: 0 };
function Bad() {
  shared.clicks += 1; // side effect in render
  return <p>{shared.clicks}</p>;
}

function Good({ clicks }: { clicks: number }) {
  return <p>{clicks}</p>;
}
```

## Where side effects belong

- **Event handlers** — user-driven changes
- **Effects** — syncing with external systems after commit
- **Not render** — no network, no random, no writing to remote stores
