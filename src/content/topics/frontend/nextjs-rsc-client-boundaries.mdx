## Why this matters

Shipping all UI as client JS hurts TTI. Server Components let you fetch close to data and send less JavaScript; Client Components opt into interactivity.

<Callout type="mental-model">
  `"use client"` marks a module-graph boundary. Push that boundary down to interactive leaves; keep layouts/pages on the server when possible.
</Callout>

## Compose server page + client leaf

Pass serializable props from Server Components into Client Components. You can also pass Server Components as children into client wrappers.

```tsx
// app/topics/[id]/page.tsx (Server Component by default)
import { LikeButton } from './like-button';
import { getTopic } from '@/lib/topics';

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const topic = await getTopic(id);
  return (
    <main>
      <h1>{topic.title}</h1>
      <LikeButton initialLikes={topic.likes} />
    </main>
  );
}

// like-button.tsx
'use client';
import { useState } from 'react';

export function LikeButton({ initialLikes }: { initialLikes: number }) {
  const [likes, setLikes] = useState(initialLikes);
  return (
    <button type="button" onClick={() => setLikes((n) => n + 1)}>
      Likes {likes}
    </button>
  );
}
```

## Common mistakes

- **Marking entire trees as client** — Unnecessary JS; lose server data benefits.
- **Passing non-serializable props** — Functions/classes across the boundary fail.
- **Importing server-only secrets into client modules** — Leak risk—use server-only barriers.
