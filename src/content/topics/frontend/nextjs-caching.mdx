## Why this matters

Without a clear cache story you either hammer origins or serve stale pages. Next.js layers caches; you must know which layer you are talking about.

<Callout type="mental-model">
  Deduplicate work within a request (React cache / fetch memoization), then decide whether cross-request caching and time/tag revalidation apply.
</Callout>

## Explicit fetch caching + tag revalidation

Defaults evolve—prefer being explicit with cache and next.revalidate/tags for production clarity.

```tsx
import { revalidateTag } from 'next/cache';

export async function getTopic(id: string) {
  const res = await fetch(`https://api.example.com/topics/${id}`, {
    next: { revalidate: 60, tags: [`topic:${id}`] },
  });
  if (!res.ok) throw new Error('topic fetch failed');
  return res.json();
}

export async function updateTopicAction(id: string) {
  'use server';
  // ...persist update...
  revalidateTag(`topic:${id}`, 'max');
}
```

## Common mistakes

- **Assuming all fetch is cached forever** — Current defaults may not cache; verify docs for your version.
- **Caching personalized data** — Risk of leaking user A data to user B.
- **Revalidating nothing after writes** — Users see stale HTML/JSON.
