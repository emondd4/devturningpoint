## What is this?

Memoization skips work when inputs are unchanged:

- `React.memo` — skip re-rendering a child if props are shallow-equal
- `useMemo` — cache an expensive calculated value
- `useCallback` — cache a function identity for referential equality

## Why it exists

By default, when a parent renders, children render too. That is usually fine. When profiling shows a hot subtree, memoization is an **opt-in** tool.

## Mental model

<Callout type="mental-model">
  Correctness first, measure second, memoize third. Memoization caches equality—not a substitute for better state placement.
</Callout>

## Example

```tsx
import { memo, useMemo, useState } from 'react';

const List = memo(function List({ items }: { items: string[] }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
});

export function Filtered({ all }: { all: string[] }) {
  const [q, setQ] = useState('');
  const items = useMemo(
    () => all.filter((x) => x.toLowerCase().includes(q.toLowerCase())),
    [all, q],
  );
  return (
    <div>
      <input value={q} onChange={(e) => setQ(e.target.value)} aria-label="Filter" />
      <List items={items} />
    </div>
  );
}
```

## When NOT to use it

- Prematurely wrapping every component in `memo`
- `useMemo` for trivial string concatenations
- Stabilizing callbacks that no memoized child needs

## Interview angles

**Mid:** Difference between `memo` and `useMemo`.  
**Senior:** A tree renders too often—describe your investigation before adding memo.
