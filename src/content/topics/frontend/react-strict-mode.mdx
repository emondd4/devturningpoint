## What is this?

**Strict Mode** is a development-only helper that surfaces unsafe lifecycle patterns and impure rendering by intentionally exercising extra invocations.

## Why it exists

Production may mount once, but impure logic still bites under concurrency, fast refresh, or future React features. Strict Mode makes those bugs loud earlier.

## Mental model

<Callout type="mental-model">
  If your effect cannot survive mount → cleanup → mount, it is not resilient. Strict Mode helps you find that.
</Callout>

## Practical guidance

1. Do not disable Strict Mode to “fix” double fetching—fix the effect/idempotency instead.
2. Keep render pure so double-rendering is harmless.
3. Ensure effects clean up subscriptions and abort controllers.

## Interview angles

**Mid:** Why do effects appear to run twice in development?  
**Senior:** How do you design data fetching to be safe under Strict Mode and concurrent rendering?
