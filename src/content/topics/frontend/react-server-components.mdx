## Why this matters

Shipping all data-fetching and UI logic to the browser inflates bundles and leaks server concerns. Server Components render on the server, keep secrets/DB access off the client, and send a serialized UI result.

## Mental model

<Callout type="mental-model">
  Default in App Router: Server Components. Add `"use client"` only for interactivity (state, effects, browser APIs). You can nest Client Components inside Server Components, not the reverse without composition patterns.
</Callout>

## How it works

Fetch in Server Components, pass serializable props to Client Components. Do not import server-only modules into client files.

```tsx
// app/topics/page.tsx — Server Component (default)
async function TopicsPage() {
  const topics = await db.topics.findMany(); // server-only
  return <TopicList initial={topics} />;
}

// TopicList.tsx
'use client';
export function TopicList({ initial }: { initial: { id: string }[] }) {
  const [q, setQ] = useState('');
  const filtered = initial.filter((t) => t.id.includes(q));
  return (
    <>
      <input value={q} onChange={(e) => setQ(e.target.value)} />
      <ul>{filtered.map((t) => <li key={t.id}>{t.id}</li>)}</ul>
    </>
  );
}
```

## Common mistakes

- **Marking everything use client** — Defeats RSC benefits.
- **Passing non-serializable props** — Functions/classes across the boundary fail.
- **Fetching secrets in client components** — Exposes keys; keep on server.
