## Why this matters

Search and social previews need correct titles/descriptions/OG images. In App Router, metadata belongs in Server Components—not ad-hoc document hacks in client trees.

<Callout type="mental-model">
  Static metadata export for shared defaults; generateMetadata when the title depends on fetched content. File conventions cover icons, OG images, sitemap, robots.
</Callout>

## generateMetadata sketch

Keep metadata generation on the server. Deduplicate shared fetches with React cache when needed.

```tsx
import type { Metadata } from 'next';

export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>;
}): Promise<Metadata> {
  const { id } = await params;
  const topic = await getTopic(id);
  return {
    title: topic.title,
    description: topic.summary,
    openGraph: { title: topic.title, description: topic.summary },
  };
}
```

## Common mistakes

- **Setting document.title only in useEffect** — Late, fragile, weaker for crawlers/SSR.
- **Client Component metadata exports** — Unsupported—use Server Components.
- **Duplicate conflicting titles** — Fix layout vs page metadata hierarchy intentionally.
