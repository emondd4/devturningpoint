## What is this?

**Batching** means React groups multiple state updates that happen close together so the UI re-renders once with the combined result—rather than rendering after every single `set` call.

## Why it exists

Without batching, clicking a button that updates three pieces of state could render three times, waste work, and show intermediate UI states users never need.

## Mental model

<Callout type="mental-model">
  Prefer describing the next state. React may apply several updates before the next paint. If a later update depends on the previous value, use the functional updater form.
</Callout>

## Functional updates

```tsx
import { useState } from 'react';

export function Score() {
  const [score, setScore] = useState(0);

  function addTwiceWrong() {
    setScore(score + 1);
    setScore(score + 1); // both read the same score snapshot
  }

  function addTwiceRight() {
    setScore((s) => s + 1);
    setScore((s) => s + 1); // second sees the queued result
  }

  return (
    <div>
      <p>{score}</p>
      <button type="button" onClick={addTwiceRight}>
        +2
      </button>
    </div>
  );
}
```

## Common mistakes

1. Assuming each `setState` immediately mutates a local variable.
2. Reading stale state inside nested timeouts without functional updates or effects.
