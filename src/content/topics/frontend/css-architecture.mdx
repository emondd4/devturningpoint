## Why this matters

Unstructured CSS becomes a specificity war. Architecture is about ownership: which rules win, where tokens live, and how features stay isolated.

<Callout type="mental-model">
  Think in layers (reset → tokens → base → components → utilities). Lower layers set defaults; higher layers opt into overrides intentionally.
</Callout>

## Cascade layers sketch

Use @layer to make priority explicit instead of escalating !important.

```css
@layer reset, tokens, base, components, utilities;

@layer tokens {
  :root {
    --space-2: 0.5rem;
    --color-fg: #111;
  }
}

@layer components {
  .card {
    padding: var(--space-2);
    color: var(--color-fg);
  }
}

@layer utilities {
  .mt-2 {
    margin-top: var(--space-2);
  }
}
```

## Common mistakes

- **!important as architecture** — Masks ordering bugs; prefer layers/specificity discipline.
- **Global class soup** — No ownership → regressions across pages.
- **Inlining one-off styles everywhere** — No shared tokens; inconsistent spacing/type.
