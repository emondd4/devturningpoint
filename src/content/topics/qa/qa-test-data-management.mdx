## Why data is half the test

Flaky and false failures often come from shared users, leftover orders, or production clones with PII. Good test data is **designed**, not scavenged.

## Mental model

<Callout type="mental-model">
  Prefer create-in-test → assert → cleanup (or transactional rollback). When sharing environments, isolate by unique prefixes and avoid mutating golden records other suites need.
</Callout>

```ts
// Conceptual Playwright setup
const email = `buyer+${Date.now()}@example.test`;
await api.createUser({ email, role: "buyer" });
// ... exercise UI ...
await api.deleteUser(email);
```

## Patterns

- Factories/builders for entities.
- Seed scripts for reference data (currencies, roles).
- Masked/synthetic data—not raw prod dumps with PII.

## Common mistakes

- **One shared admin password in docs** — Collisions and mystery state.
- **Prod data in local DB** — Privacy and surprise deletes.
- **No cleanup** — Environments rot until someone resets.

## Interview angle

<Callout type="interview">
  How do you keep parallel CI workers from fighting over the same test user?
</Callout>

## Practice checklist

- [ ] Design a factory for “order with 2 line items”.
- [ ] List PII fields you must never copy from prod.
- [ ] Add cleanup to one automated flow.
