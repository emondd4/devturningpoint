## Why QA cares about security

You may not be a penetration tester, but you can catch missing authz, sensitive data leaks, and insecure defaults before release.

## Mental model

<Callout type="mental-model">
  Use OWASP Top 10 as a risk lens: for each feature ask “what if an attacker or curious user abuses this?” Verify negative cases—forbidden roles, tampered IDs, unexpected payloads—not only happy paths.
</Callout>

## Awareness tests (non-exhaustive)

- Horizontal/vertical privilege checks (IDOR-style).
- Session logout and cookie flags at a high level.
- Basic XSS/input reflection in UI fields.
- CSRF awareness on cookie-authenticated state changes (see fullstack CSRF topic).

## Common mistakes

- **Only testing as admin** — Miss authorization bugs.
- **Storing secrets in bug tickets** — Protect PII and tokens.
- **Calling yourself a pentester after a checklist** — Know limits; escalate.

## Interview angle

<Callout type="interview">
  How would you test that user A cannot access user B’s invoices via the API?
</Callout>

## Practice checklist

- [ ] Map Top 10 items to your product surfaces.
- [ ] Add two negative authz cases to API tests.
- [ ] Review one PR for security-relevant AC.
