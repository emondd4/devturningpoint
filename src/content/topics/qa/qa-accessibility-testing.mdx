## Why a11y is QA’s job too

Accessibility defects are product bugs. Laws and customers increasingly expect WCAG-aligned experiences.

## Mental model

<Callout type="mental-model">
  Combine automated rules (axe) with human checks: keyboard-only paths, focus visibility, form labels, error announcements, and basic screen-reader smoke. Automation catches low-hanging fruit; humans catch UX semantics.
</Callout>

## Practical checks

- Tab order and focus traps in modals.
- Name, role, value for controls.
- Contrast on text and UI states.
- Playwright + axe in CI for regressions.

## Common mistakes

- **Color-only status** — Failures invisible to color-blind users.
- **Placeholder-as-label** — Screen readers and recall suffer.
- **“We’ll fix a11y later”** — Expensive remediations.

## Interview angle

<Callout type="interview">
  How do you test a modal dialog for keyboard and screen-reader users?
</Callout>

## Practice checklist

- [ ] Keyboard-only complete a signup flow.
- [ ] Run axe on one page and triage violations.
- [ ] Add one a11y assertion to Playwright.
