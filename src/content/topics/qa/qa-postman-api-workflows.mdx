## Why Postman still matters

Teams collaborate on HTTP collections as living documentation and executable checks—especially useful before full code-based API suites exist.

## Mental model

<Callout type="mental-model">
  Environment variables hold base URLs and secrets (never commit secrets). Pre-request scripts set auth; tests assert status, schema, and business fields. Folders mirror API domains; CI runs collections headlessly.
</Callout>

## Workflow tips

- Separate local/staging environments.
- Chain requests with saved variables (login → token → protected call).
- Contract-ish checks: required fields and types.
- Export and version collections thoughtfully.

## Common mistakes

- **Hard-coded tokens in shared collections** — Rotate and use secrets vaults.
- **Only 200 assertions** — Miss authorization and validation errors.
- **No cleanup** — Polluting shared staging data.

## Interview angle

<Callout type="interview">
  How do you structure a Postman collection for auth + CRUD of a resource?
</Callout>

## Practice checklist

- [ ] Build a three-request folder with env vars.
- [ ] Add negative tests (401/403/422).
- [ ] Sketch how Newman would run in CI.
