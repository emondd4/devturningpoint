## Why performance awareness

Functional pass ≠ production ready. Latency and error rates under concurrency are product risks.

## Mental model

<Callout type="mental-model">
  Define SLOs (e.g., p95 latency, error rate) → model realistic traffic → run load/stress/soak → observe app + infra metrics → decide go/no-go. k6 is script-as-code friendly; JMeter remains common in enterprise GUI-driven setups.
</Callout>

## Test types

- **Load** — Expected peak.
- **Stress** — Beyond peak to find breaking points.
- **Soak** — Long duration for leaks and degradation.

## Common mistakes

- **Hammering without baselines** — Numbers without meaning.
- **Testing only the homepage** — Miss hot APIs and DB locks.
- **Ignoring warm-up and think time** — Unrealistic traffic shapes.

## Interview angle

<Callout type="interview">
  How would you performance-test a checkout API before a campaign sale?
</Callout>

## Practice checklist

- [ ] Write a tiny k6 script against a public or local API.
- [ ] Pick two SLIs for your product.
- [ ] Pair with DevOps on dashboards during a test.
