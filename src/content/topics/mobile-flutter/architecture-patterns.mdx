## Why architecture shows up in interviews and outages

Feature velocity dies when UI widgets call SDKs directly. A simple layering—UI → state/notifier → repositories → data sources—keeps Firebase/SQLite/HTTP swappable and testable.

## Mental model

<Callout type="mental-model">
  Start from use cases, not folder fashion. Put framework details (Flutter widgets, Dio, Firestore) at the edges. Domain rules stay pure Dart when possible.
</Callout>

## How

### Repository boundary

```dart
abstract class OrderRepository {
  Future<List<Order>> listOpen();
}

class HttpOrderRepository implements OrderRepository {
  HttpOrderRepository(this.client);
  final ApiClient client;

  @override
  Future<List<Order>> listOpen() async {
    final json = await client.getJson('/orders?status=open');
    return json.map(Order.fromJson).toList();
  }
}
```

## Common mistakes

- **Creating 12 layers for a two-screen app**
- **“Clean architecture” folders that still import Flutter in domain**
- **Sharing one global mutable singleton for everything**
