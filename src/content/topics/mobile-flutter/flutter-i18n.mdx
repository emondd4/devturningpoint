## Why hardcoded English strings fail products

Bangladesh and global apps need Bangla (and often RTL-aware layout for other locales). Hardcoded `Text('Submit')` blocks translators and creates inconsistent copy.

## Mental model

<Callout type="mental-model">
  Separate **messages** (ARB/JSON) from widgets. `Localizations` (an InheritedWidget descendant) supplies the active locale. Format dates/numbers with locale-aware formatters—not string concat.
</Callout>

## Approach

1. Enable Flutter gen-l10n / official internationalization workflow.
2. Keep placeholders for names and counts (`{count, plural, ...}` patterns where supported).
3. Test font coverage for Bangla glyphs.

```dart
// After codegen, widgets typically call something like:
// Text(AppLocalizations.of(context)!.submit);
```

Also localize store listings and push notification text—not only in-app UI.

## Common mistakes

- Concatenating sentences (`'Hello ' + name`) breaking grammar in other languages
- Ignoring text overflow when Bangla strings are longer
- Forgetting device locale vs in-app language switcher

## Interview angle
