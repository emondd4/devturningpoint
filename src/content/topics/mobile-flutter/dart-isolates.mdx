## Why Flutter’s UI runs on the main isolate’s event loop. A multi-megabyte JSON parse on that isolate janks frames—even if you `await` it. Isolates give separate memory heaps and true parallel CPU use on native platforms.

## Mental model

<Callout type="mental-model">
  Isolates do not share memory; they communicate by message passing (SendPort/ReceivePort). Prefer `Isolate.run` for one-shot work; long-lived workers when you repeatedly pay spawn costs.
</Callout>

## How

### One-shot background compute

```dart
import 'dart:convert';
import 'dart:isolate';

Future<Map<String, dynamic>> parseJsonOffMain(String raw) {
  return Isolate.run(() {
    final decoded = jsonDecode(raw);
    return Map<String, dynamic>.from(decoded as Map);
  });
}
```

## Common mistakes

- **Assuming isolates work the same on Flutter web** — limited/unsupported patterns.
- **Sending huge object graphs** — copy cost can dominate.
- **Using isolates for tiny work** — spawn overhead exceeds benefit.

## Interview angle

<Callout type="interview">
  Why can an awaited CPU-heavy function still freeze Flutter UI, and how do isolates change that?
</Callout>

## Practice checklist

- [ ] Move a large JSON decode behind `Isolate.run`.
- [ ] Profile jank before/after with DevTools.
- [ ] Sketch a long-lived worker with ports (even if you do not ship it).
