## Why platform channels exist

Flutter cannot wrap every OS API. Battery level, proprietary SDKs, and OEM quirks still live in Kotlin/Swift. Platform channels are the message bus between Dart and host code.

## Mental model

<Callout type="mental-model">
  Agree on a channel name and method names. Dart invokes; native handlers reply with success/error. Data is serialized through standard codecs. Prefer typed approaches (Pigeon) for larger surfaces.
</Callout>

## How

### Dart side MethodChannel call

```dart
import 'package:flutter/services.dart';

class BatteryApi {
  static const _channel = MethodChannel('com.example/battery');

  Future<int> getBatteryLevel() async {
    try {
      final level = await _channel.invokeMethod<int>('getBatteryLevel');
      return level ?? -1;
    } on PlatformException catch (e) {
      throw StateError('Battery failed: ${e.message}');
    }
  }
}
```

## Common mistakes

- **Doing heavy work on the UI platform thread**
- **Mismatched channel names** across Android/iOS
- **Passing unsupported types** without a custom codec
