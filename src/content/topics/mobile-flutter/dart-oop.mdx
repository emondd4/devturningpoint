## Why Flutter apps are object graphs. Weak OOP habits produce god widgets, untestable models, and inheritance trees nobody can change.

## Mental model

<Callout type="mental-model">
  Prefer composition over deep inheritance. Use abstract classes/interfaces for contracts, mixins for reusable behavior, and const constructors for immutable values in UI.
</Callout>

## How

### Classes and interfaces

Dart classes can implement multiple interfaces. Abstract classes define contracts without forcing a single hierarchy.

```dart
abstract class AuthRepository {
  Future<User?> currentUser();
}

class ApiAuthRepository implements AuthRepository {
  ApiAuthRepository(this.client);
  final ApiClient client;

  @override
  Future<User?> currentUser() => client.getMe();
}

mixin Logging {
  void log(String message) => print('[log] $message');
}

class SessionService with Logging {
  void start() => log('session start');
}
```

## Common mistakes

- **Deep inheritance for UI** — prefer composing widgets.
- **Mutable public fields** — break equality and rebuild reasoning.
- **Mixing network + UI in model classes** — untestable.

## Interview angle

## Practice checklist

- [ ] Implement a repository interface with a fake for tests.
