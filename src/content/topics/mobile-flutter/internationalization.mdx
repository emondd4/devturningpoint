## Why hard-coded English strings fail products

Bangladesh and global apps need Bangla/English (and more). Locale changes should rebuild UI via the same InheritedWidget mechanics as themes.

## Mental model

<Callout type="mental-model">
  MaterialApp/CupertinoApp take `localizationsDelegates` and `supportedLocales`. Load string catalogs through generated or manual Localizations delegates; format dates/numbers with locale APIs.
</Callout>

## How

### Wire supported locales

```dart
import 'package:flutter_localizations/flutter_localizations.dart';

MaterialApp(
  localizationsDelegates: const [
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  supportedLocales: const [
    Locale('en'),
    Locale('bn'),
  ],
  home: const HomePage(),
);
```

## Common mistakes

- **Concatenating translated fragments** — breaks grammar in many languages
- **Forgetting RTL layout testing** when expanding locales
- **Embedding locale logic deep in widgets** without Localizations

## Interview angle

<Callout type="interview">
  How does Localizations cause dependent widgets to rebuild when the device locale changes?
</Callout>
