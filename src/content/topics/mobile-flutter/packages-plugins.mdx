## Why dependency choice is architecture

Every package is code you did not write but must secure and upgrade. Plugins may include native Android/iOS projects—supply-chain and maintenance matter.

## Mental model

<Callout type="mental-model">
  Prefer well-maintained packages with clear licenses, Flutter 3 compatibility, and issue response. Pin versions thoughtfully; read changelogs before major bumps.
</Callout>

## How

### Declare dependencies

```dart
# pubspec.yaml (illustrative)
# dependencies:
#   http: ^1.2.0
#   # Prefer official or widely used plugins for camera/maps/etc.
```

## Common mistakes

- **Adding five packages to avoid 20 lines of code**
- **Ignoring discontinued plugins**
- **Not testing plugin upgrades on both Android and iOS**

## Interview angle

<Callout type="interview">
  How do you evaluate whether to vendor a thin wrapper yourself instead of depending on a stale plugin?
</Callout>

## Practice checklist

- [ ] Audit pubspec for unused deps.
- [ ] Check last publish date of a critical plugin.
- [ ] Read Flutter using-packages docs.
