## Why raw Map of String to dynamic does not scale

APIs speak JSON; your app speaks domain types. Casting maps everywhere produces null crashes and typo bugs. Explicit `fromJson`/`toJson` (or codegen) is the boundary.

## Mental model

<Callout type="mental-model">
  Decode once at the edge into immutable models. Validate required fields. For large payloads, decode off the UI isolate.
</Callout>

## How

### Manual model mapping

```dart
class Article {
  const Article({required this.id, required this.title});
  final String id;
  final String title;

  factory Article.fromJson(Map<String, dynamic> json) {
    final id = json['id'];
    final title = json['title'];
    if (id is! String || title is! String) {
      throw FormatException('Invalid Article json: $json');
    }
    return Article(id: id, title: title);
  }

  Map<String, dynamic> toJson() => {'id': id, 'title': title};
}
```

## Common mistakes

- **Trusting every field without type checks**
- **Parsing giant JSON on the UI isolate**
- **Mutable models shared across widgets** — hard rebuild reasoning

## Interview angle

<Callout type="interview">
  Compare hand-written fromJson vs code generation—what are tradeoffs for a 5-model app vs a 80-model app?
</Callout>

## Practice checklist

- [ ] Write fromJson for a nested response.
- [ ] Throw on unexpected shapes instead of silent nulls.
