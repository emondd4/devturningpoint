## Why not every dependency should be a plugin

Packages share Dart code. Plugins add Android/iOS (and other) native implementations. Each plugin increases build complexity and platform failure surface.

## Mental model

<Callout type="mental-model">
  Prefer **pure Dart** packages when possible. Prefer **maintained plugins** over writing channels. Read pub.dev scores, platforms supported, and last publish date before adopting.
</Callout>

## Adding deps

```yaml
# pubspec.yaml
dependencies:
  http: ^1.2.0
  shared_preferences: ^2.3.0
```

```bash
flutter pub get
flutter pub outdated
```

Commit `pubspec.lock` for apps so CI resolves the same graph.

## Common mistakes

- Depending on abandoned plugins pinned to old Android embeddings
- Adding five plugins for one permission prompt
- Ignoring license obligations for shipping binaries
