## Why CI/CD is a mobile reliability feature

Manual Xcode/Android Studio clicks do not scale. CI runs analyzer/tests on every PR; CD produces signed artifacts and can upload to Play/TestFlight with audited secrets.

## Mental model

<Callout type="mental-model">
  Pipeline stages: resolve deps → analyze → unit/widget tests → build apk/ipa/appbundle → sign with secrets from a vault → distribute. Fail closed on test/analyze errors.
</Callout>

## How

### Example job sketch (GitHub Actions-like)

```dart
# Conceptual — adapt to your CI product
# - flutter pub get
# - dart analyze
# - flutter test
# - flutter build appbundle --release
# Store keystore / API keys as encrypted CI secrets, never in git.
```

## Common mistakes

- **Committing keystores or provisioning profiles**
- **Only building on one developer’s machine**
- **Skipping tests “to ship faster”** — regressions ship faster too

## Interview angle

<Callout type="interview">
  What secrets belong in CI, and how do you rotate a Play upload key compromise?
