## Why teams reach for Firebase

Many Flutter products need auth, push, analytics, and a managed backend quickly. Firebase can shorten time-to-MVP—but security rules, cost, and vendor coupling are real.

## Mental model

<Callout type="mental-model">
  Treat Firebase as a set of cloud services behind repositories. Never put privileged secrets in the client. Design data models and security rules together.
</Callout>

## How

### Setup mindset (not a full project)

```dart
// After flutterfire configure / official setup:
// - Initialize Firebase in main()
// - Keep Auth/Firestore access behind repository interfaces
// - Enforce App Check + security rules for production

abstract class UserProfileRepository {
  Stream<UserProfile?> watchProfile(String uid);
}
```

## Common mistakes

- **Open Firestore rules in production “temporarily”**
- **Business logic only in the client** — rules must encode authorization
- **Unbounded realtime listeners** — battery and cost
