## Why accessibility is quality, not a niche checkbox

Inaccessible apps exclude users and fail enterprise/government procurement. Flutter exposes semantics to platform screen readers—if you wire them.

## Mental model

<Callout type="mental-model">
  Provide semantic labels/buttons, keep 48×48 tap targets, maintain contrast, and test with TalkBack/VoiceOver before release.
</Callout>

## How

### Semantics and buttons that do something

```dart
Semantics(
  label: 'Add to cart',
  button: true,
  child: IconButton(
    icon: const Icon(Icons.add_shopping_cart),
    onPressed: () {
      // Always provide a real action — avoid no-op handlers in release UI
    },
  ),
);
```

## Common mistakes

- **Icon-only controls without labels**
- **Tiny tap targets**
- **Auto-advancing focus/context while the user types**

## Interview angle

<Callout type="interview">
  How do you verify a Flutter screen with VoiceOver, and what failures do you look for first?
</Callout>

## Practice checklist

- [ ] Run TalkBack or VoiceOver on a form screen.
- [ ] Add Semantics labels to icon buttons.
- [ ] Check contrast for primary text.
