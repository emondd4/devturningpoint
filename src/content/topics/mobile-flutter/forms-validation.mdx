## Why forms need a first-class pattern

Login, checkout, and KYC screens fail when validation is ad-hoc `if` soup. Flutter’s `Form` aggregates field validators and surfaces errors consistently.

## Mental model

<Callout type="mental-model">
  Keep a `GlobalKey<FormState>` on a StatefulWidget. `validate()` runs each field validator; return a String error or null. Save only after validation succeeds.
</Callout>

## How

### Cookbook-style form

```dart
class LoginForm extends StatefulWidget {
  const LoginForm({super.key});
  @override
  State<LoginForm> createState() => _LoginFormState();
}

class _LoginFormState extends State<LoginForm> {
  final _formKey = GlobalKey<FormState>();
  final _email = TextEditingController();

  @override
  void dispose() {
    _email.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Form(
      key: _formKey,
      child: Column(
        children: [
          TextFormField(
            controller: _email,
            decoration: const InputDecoration(labelText: 'Email'),
            validator: (v) {
              if (v == null || v.isEmpty) return 'Email required';
              if (!v.contains('@')) return 'Enter a valid email';
              return null;
            },
          ),
          ElevatedButton(
            onPressed: () {
              if (_formKey.currentState?.validate() ?? false) {
                // submit
              }
            },
            child: const Text('Continue'),
          ),
        ],
      ),
    );
  }
}
```

## Common mistakes

- **Recreating GlobalKey every build**
- **Forgetting to dispose controllers**
- **Only validating on the server** — still validate client UX, then enforce server-side
