## Why Before records, multi-returns became ad-hoc maps or tiny classes. Records + patterns make destructuring and exhaustive switches a first-class language feature (Dart 3+).

## Mental model

<Callout type="mental-model">
  Records are immutable, fixed-shape, structurally typed aggregates. Patterns match and destructure values in switches, declarations, and for-loops—refutable patterns can fail to match.
</Callout>

## How

### Records as multiple returns

```dart
(String, int) userInfo(Map<String, Object?> json) {
  return (json['name'] as String, json['age'] as int);
}

void main() {
  final (name, age) = userInfo({'name': 'Nila', 'age': 22});
  print('$name is $age');

  final shape = (x: 1, y: 2);
  switch (shape) {
    case (x: final x, y: final y) when x == y:
      print('diagonal-ish');
    case (x: _, y: _):
      print('point');
  }
}
```

## Common mistakes

- **Overusing records instead of named domain types** for public APIs.
- **Unsafe casts from JSON** without validation.
- **Non-exhaustive switches** on sealed-like hierarchies.
