## Why anti-patterns cost real users

Janky lists, untestable widgets, and mysterious setState loops come from a small set of recurring mistakes. Naming them makes code review faster.

## Mental model

<Callout type="mental-model">
  Prefer small widgets, localized rebuilds, async-safe context, typed models, and clear state ownership. Profile before micro-optimizing.
</Callout>

## How

### Anti-pattern → better shape

```dart
// Anti-pattern: setState at root for every keystroke in a huge tree
// Better: TextField local state or a selective provider

// Anti-pattern: jsonDecode(huge) in build()
// Better: parse in repository / Isolate.run, cache model

Widget build(BuildContext context) {
  // Do not start network calls directly in build without caching strategy
  return const SizedBox.shrink();
}
```

## Common mistakes

- **Business logic inside build methods**
- **Ignoring const constructors where possible**
- **Giant Build methods (500+ lines)**
