## Why “it works on my emulator” fails stores

Flutter abstracts UI, not OS policy. Android cleartext blocks, iOS ATS, permission dialogs, background execution limits, and store review guidelines still own your release fate.

## Mental model

<Callout type="mental-model">
  Maintain a platform checklist per release: network security, privacy manifests/permissions rationale, icon/splash, signing, and minimum OS versions.
</Callout>

## How

### Prefer HTTPS everywhere

```dart
// Conceptual checklist in code comments / CI gates:
// 1) No production cleartext HTTP
// 2) Declare only needed permissions
// 3) Test permission denial paths (camera/photos/location)
// 4) Verify deep links / app links per platform
// 5) Exercise TalkBack + VoiceOver smoke paths

bool get isHttpsApi => apiBase.startsWith('https://');
```

## Common mistakes

- **Shipping broad cleartext exceptions**
- **Requesting permissions before explaining why**
- **Ignoring iOS privacy nutrition labels / Android data safety forms**

## Interview angle

<Callout type="interview">
  An HTTP API works on iOS simulator but fails on Android emulator—what is a likely cause?
</Callout>

## Practice checklist

- [ ] Read Android network security / cleartext notes.
- [ ] List permissions your app needs and denial UX.
- [ ] Compare minSdk / iOS deployment target with team policy.
