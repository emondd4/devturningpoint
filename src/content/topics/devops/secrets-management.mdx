## Why `.env` in git is an incident waiting to happen

API keys in repositories leak via forks, screenshots, and CI logs. Secrets need storage, access control, injection at runtime, and rotation.

## Mental model

<Callout type="mental-model">
  Store secrets outside the artifact; grant least privilege to fetch them; inject at process start; rotate when people leave or leaks are suspected.
</Callout>

```yaml
# GitHub Actions — reference, never echo
- name: Run migrations
  env:
    DATABASE_URL: ${{ secrets.DATABASE_URL }}
  run: npm run migrate
```

In AWS, prefer IAM roles + Secrets Manager/SSM Parameter Store over long-lived access keys in app config.

## Common mistakes

- **Printing secrets in debug logs** — Mask CI outputs; never `echo $SECRET`.
- **One shared prod password forever** — Plan rotation and dual-run cutovers.
- **Secrets in client-side bundles** — Frontends cannot keep app secrets.

## Interview angle

<Callout type="interview">
  Compare GitHub Actions encrypted secrets with a cloud secrets manager for a production API.
</Callout>

## Practice checklist

- [ ] Move a local secret into CI secrets.
- [ ] Sketch rotation for a DB password.
- [ ] Audit a repo for accidental key patterns.
