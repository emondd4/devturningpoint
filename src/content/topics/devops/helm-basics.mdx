## Why raw kubectl YAML does not scale

Ten microservices × three environments × copy-pasted manifests drifts. Helm charts parameterize releases with values files and versioned packages.

## Mental model

<Callout type="mental-model">
  A chart is a versioned template package. A release is an installed instance with values. Templates render Kubernetes objects; upgrades track revision history.
</Callout>

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm install my-redis bitnami/redis --set auth.password='change-me'
helm list
helm upgrade my-redis bitnami/redis -f values-prod.yaml
```

Prefer your own charts for app Deployments; use well-known charts carefully with pinned versions.

## Common mistakes

- **Huge god-charts** — Split by ownership boundaries.
- **Secrets only in values committed to git** — Use sealed secrets / external secret ops patterns.
- **Ignoring `helm diff` / dry-run** — Always review rendered manifests.
