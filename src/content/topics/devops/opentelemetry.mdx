## Why proprietary agents lock you in

Swapping APM vendors should not mean rewriting instrumentation. OpenTelemetry standardizes signals and context propagation across languages.

## Mental model

<Callout type="mental-model">
  Apps create spans (traces), instruments (metrics), and logs with shared context. An SDK + exporter ships OTLP to a collector or backend. Trace IDs stitch requests across services.
</Callout>

```bash
# Conceptual collector pipeline sketch
# receivers: [otlp] → processors: [batch] → exporters: [otlp/jaeger, prometheus]
```

Start with auto-instrumentation where available; add custom spans around business-critical boundaries (payments, auth).

## Common mistakes

- **Tracing everything at 100% in huge fleets** — Sample thoughtfully.
- **Missing context propagation** — Broken traces across HTTP/gRPC.
- **Metrics cardinality explosions** — High-cardinality labels kill backends.

## Interview angle

<Callout type="interview">
  Explain how a single user request becomes a distributed trace across API and worker services.
</Callout>

## Practice checklist

- [ ] Read OTel signals overview.
- [ ] Enable auto-instrumentation for one language demo.
- [ ] Correlate a log line with a trace id.
