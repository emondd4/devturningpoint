## Why GitOps caught on

Click-ops drifts. GitOps stores desired cluster state in git; a controller continuously reconciles reality to that state—auditable, reviewable, revertible.

## Mental model

<Callout type="mental-model">
  Git is the source of truth for declarative config. Humans merge PRs; agents apply. Rollbacks are `git revert` + sync, not SSH edits.
</Callout>

```text
dev PR → main → CI builds image → updates manifest tag in git → Argo CD syncs cluster
```

## Common mistakes

- **Secrets in plain git** — Use sealed/external secrets patterns.
- **Bypassing git with kubectl apply forever** — Drift returns.
- **Giant mono-manifests without review discipline** — Dangerous “apply all”.

## Interview angle

<Callout type="interview">
  Compare a classic CI push deploy with a pull-based GitOps controller for Kubernetes.
</Callout>

## Practice checklist

- [ ] Sketch a GitOps flow for one service.
