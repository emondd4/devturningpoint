## Why this matters

Dev images with compilers and npm caches are huge and increase attack surface. Multi-stage builds separate build-time and run-time concerns.

<Callout type="mental-model">
  Stage 1 installs deps and builds. Stage 2 copies dist + production node_modules (or a compiled binary) onto a minimal base.
</Callout>

## Node API sketch

Run as non-root when possible; pin base digests in real pipelines.

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build && npm prune --omit=dev

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
COPY package*.json ./
USER node
CMD ["node", "dist/main.js"]
```

## Common mistakes

- **Shipping build toolchain to prod** — Larger image, more CVEs.
- **Running as root** — Container breakout blast radius.
- **Not caching package manifests first** — Slow rebuilds.
