## Why this matters

You must maintain auth state somehow. JWTs push claims to the client; sessions keep authoritative state on the server. Neither is magic—threat models differ.

<Callout type="mental-model">
  Sessions: opaque id in cookie → server lookup (revocable, easy logout). JWT access tokens: verifiable without store (scalable) but revocation is harder—often pair with short TTL + refresh rotation.
</Callout>

## Decision cues

Browser-first apps often use secure, HttpOnly cookies (session or refresh). Pure APIs for third parties may use bearer access tokens with clear storage guidance.

```ts
export type AuthStyle = 'server-session' | 'jwt-bearer';

export function recommendAuth(style: 'spa-same-site' | 'public-api'): AuthStyle {
  return style === 'spa-same-site' ? 'server-session' : 'jwt-bearer';
}
```

## Common mistakes

- **Storing JWT in localStorage** — XSS can steal it—prefer HttpOnly cookies when possible.
- **Year-long JWT without revocation** — Stolen tokens live forever.
- **Assuming JWT is "more secure"** — Security depends on storage, TLS, rotation, and XSS posture.
