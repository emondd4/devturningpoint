## Why this matters

Emails, image processing, and fan-out notifications make requests slow and fragile. Queues move work out of the request/response path with retries and concurrency controls.

<Callout type="mental-model">
  Producers enqueue jobs; workers consume them. Redis backs Bull/BullMQ. Design jobs to be idempotent—at-least-once delivery is common.
</Callout>

## Conceptual producer

Prefer BullMQ for new Nest work (`@nestjs/bullmq`). Keep payloads small; store large blobs in object storage and pass ids.

```ts
// Conceptual — wire via @nestjs/bullmq in real apps
export type SendEmailJob = {
  to: string;
  templateId: string;
  idempotencyKey: string;
};

export async function enqueueWelcomeEmail(
  queue: { add: (name: string, data: SendEmailJob) => Promise<unknown> },
  job: SendEmailJob,
) {
  await queue.add('welcome-email', job);
}
```

## Common mistakes

- **Non-idempotent workers** — Retries duplicate charges/emails.
- **Huge payloads in Redis** — Memory pressure; pass references instead.
- **Doing queue work inline in HTTP** — Timeouts and poor UX under load.
