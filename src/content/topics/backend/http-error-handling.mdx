## Why this matters

Inconsistent errors force every client to special-case. Leaking stack traces or SQL errors is a security issue. Clear status + stable machine-readable codes speed debugging.

## Mental model

<Callout type="mental-model">
  4xx = client can fix the request. 5xx = server/dependency failed. Domain exceptions translate at the edge (filter/middleware). Logs keep detail; responses stay safe.
</Callout>

## How it works

Throw typed exceptions (`NotFoundException`, custom domain errors). Use a global filter for shape `{ code, message, details? }`. Never return raw DB errors to clients.

```ts
import {
  Catch, ExceptionFilter, ArgumentsHost, HttpException, HttpStatus,
} from '@nestjs/common';

@Catch()
export class ApiExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;
    const message =
      exception instanceof HttpException
        ? exception.message
        : 'Internal error';
    res.status(status).json({ code: 'ERR_' + status, message });
  }
}
```

## Common mistakes

- **200 OK with error payloads** — Breaks HTTP semantics and intermediaries.
- **Exposing stack traces in prod** — Information leak.
- **Using 500 for not-found** — Hides client mistakes and pollutes alerts.
