## Why this matters

Polling wastes requests for live feeds, chats, and collaborative UIs. WebSockets keep a channel open—but sticky sessions, reconnects, and auth become your problem.

## Mental model

<Callout type="mental-model">
  HTTP upgrades to a duplex socket. Server pushes events; clients send commands. Horizontal scale needs a pub/sub backplane (often Redis) so any instance can notify any connection.
</Callout>

## How it works

Authenticate on connect. Authorize per room/event. Heartbeat and reconnect. Do not put heavy business transactions only on ephemeral socket messages without persistence.

```ts
import {
  WebSocketGateway, WebSocketServer, SubscribeMessage, MessageBody,
} from '@nestjs/websockets';
import { Server } from 'socket.io';

@WebSocketGateway({ cors: { origin: '*' } })
export class TopicsGateway {
  @WebSocketServer()
  server: Server;

  @SubscribeMessage('topics:subscribe')
  handleSubscribe(@MessageBody() track: string) {
    // join a room; validate auth in a real app
    return { event: 'topics:subscribed', data: { track } };
  }

  broadcastTopicUpdated(id: string) {
    this.server.emit('topics:updated', { id });
  }
}
```

## Common mistakes

- **No auth on handshake** — Open sockets become an abuse channel.
- **Single-node assumptions** — Add Redis adapter before multi-instance deploy.
- **Using WS as the only source of truth** — Persist critical events; sockets drop.
