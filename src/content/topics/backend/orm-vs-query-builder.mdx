## Why this matters

Teams need productivity and safety around SQL. ORMs map rows to objects; query builders help compose SQL safely; raw SQL remains essential for complex plans.

<Callout type="mental-model">
  Use ORM for straightforward CRUD and relations. Use query builder/SQL for reporting, tricky joins, and performance-critical paths. Measure with EXPLAIN.
</Callout>

## Illustrative contrast

Avoid N+1 by explicit joins/relations loading. Keep transactions at the use-case boundary.

```ts
// Pseudo-contrast — APIs differ by library
// ORM-style:
// await topicsRepo.find({ where: { track: 'backend' } });

// Query-builder-style:
// await db.selectFrom('topics').selectAll().where('track', '=', 'backend').execute();
export function chooseDataAccess(kind: 'crud' | 'report'): 'orm' | 'sql' {
  return kind === 'crud' ? 'orm' : 'sql';
}
```

## Common mistakes

- **N+1 via lazy relations** —  latent query storms in production.
- **ORM-only dogma** — Some queries are clearer and faster in SQL.
- **String-concatenated SQL** — Injection risk—parameterize always.
