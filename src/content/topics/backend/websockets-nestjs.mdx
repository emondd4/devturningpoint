## Why this matters

Some UX needs server-initiated updates (chat, live dashboards). Polling wastes traffic; WebSockets keep a bidirectional channel.

<Callout type="mental-model">
  A Nest gateway is an event-driven controller for sockets. Authenticate the handshake; authorize room joins; prefer events with clear payloads.
</Callout>

## Gateway sketch

Keep business logic in services; treat the gateway as a transport adapter.

```ts
import { SubscribeMessage, WebSocketGateway, WebSocketServer } from '@nestjs/websockets';
import type { Server } from 'socket.io';

@WebSocketGateway({ namespace: '/live' })
export class LiveGateway {
  @WebSocketServer()
  server!: Server;

  @SubscribeMessage('ping')
  handlePing(): { event: string; data: string } {
    return { event: 'pong', data: 'ok' };
  }
}
```

## Common mistakes

- **Skipping auth on upgrade** — Anyone can subscribe to private rooms.
- **Pushing huge payloads** — Backpressure and battery drain on mobile.
- **Using WS for simple CRUD** — HTTP/REST is simpler and cacheable.
