## Why this matters

Hand-writing every SQL string slows teams; uncontrolled ORMs hide N+1 and weak transactions. Knowing Prisma vs TypeORM tradeoffs helps you pick deliberately.

## Mental model

<Callout type="mental-model">
  Prisma: schema-first, generated client, strong DX migrations. TypeORM: Active Record/Data Mapper styles, decorators, flexible but easier to misuse. Both need explicit query discipline for hot paths.
</Callout>

## How it works

Use ORM for CRUD and migrations velocity. Drop to SQL/EXPLAIN for complex reporting. Watch relations loading strategies to avoid N+1.

```ts
// Prisma-style read
const topics = await prisma.topic.findMany({
  where: { track: 'backend' },
  include: { tags: true }, // careful: can over-fetch
});

// TypeORM-style query builder
const rows = await dataSource
  .getRepository(Topic)
  .createQueryBuilder('t')
  .where('t.track = :track', { track: 'backend' })
  .getMany();
```

## Common mistakes

- **Lazy-loading in loops** — Classic N+1.
- **Business logic only in ORM hooks** — Hard to test and reason about.
- **Ignoring migration review** — Destructive schema changes need care.
