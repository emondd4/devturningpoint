## Why this matters

Killing a process mid-request causes 502s and partial writes. Orchestrators send SIGTERM first—your app should drain, then exit cleanly.

## Mental model

<Callout type="mental-model">
  SIGTERM → stop new work / fail readiness → finish in-flight HTTP → close DB/queue clients → process.exit. Bound with a timeout so hung work cannot block forever.
</Callout>

## How it works

Enable Nest `enableShutdownHooks`. Close the HTTP server, then providers. Align readiness probes with “accepting traffic” state.

```ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.enableShutdownHooks(); // listen for SIGTERM/SIGINT
  await app.listen(3000);
}
bootstrap();

// In a provider:
// async onModuleDestroy() { await this.pool.end(); }
```

## Common mistakes

- **Ignoring SIGTERM** — Platform kills you after grace period anyway—worse outcome.
- **Long unbounded drain** — Always set a hard timeout.
- **Readiness still Ready while draining** — Load balancers keep sending traffic.
