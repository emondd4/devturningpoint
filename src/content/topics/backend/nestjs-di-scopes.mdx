## Why this matters

DI is how Nest replaces manual singletons with testable wiring. Scopes control lifetime: most services should be singletons; request scope is for per-request state—and it has a cost.

<Callout type="mental-model">
  Default providers are application singletons. REQUEST creates an instance per inbound request and bubbles to dependents. TRANSIENT gives each consumer its own instance.
</Callout>

## Declaring a request-scoped provider

Use request scope sparingly; prefer passing explicit context over making the whole graph request-scoped.

```ts
import { Injectable, Scope } from '@nestjs/common';

@Injectable({ scope: Scope.REQUEST })
export class RequestContextService {
  userId?: string;
}
```

## Common mistakes

- **Request-scoping everything** — Performance/memory overhead; harder reasoning.
- **new Service() inside providers** — Bypasses DI and testing seams.
- **Ignoring scope bubble-up** — A singleton depending on request scope becomes request-scoped.
