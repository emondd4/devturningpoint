## Why this matters

Untrusted input is the root of many incidents. Validating in controllers ad-hoc is inconsistent; pipes make validation a cross-cutting boundary.

<Callout type="mental-model">
  Pipes transform/validate arguments before handlers run. ValidationPipe + class-validator decorators keep rules next to DTO shapes.
</Callout>

## Global ValidationPipe sketch

Enable whitelist/forbidNonWhitelisted to drop or reject unknown fields; transform to hydrate DTO class instances.

```ts
import { IsEmail, IsString, MinLength } from 'class-validator';
import { Body, Controller, Post, ValidationPipe } from '@nestjs/common';

export class CreateUserDto {
  @IsEmail()
  email!: string;

  @IsString()
  @MinLength(8)
  password!: string;
}

@Controller('users')
export class UsersController {
  @Post()
  create(
    @Body(
      new ValidationPipe({
        whitelist: true,
        forbidNonWhitelisted: true,
        transform: true,
      }),
    )
    body: CreateUserDto,
  ) {
    return { email: body.email };
  }
}
```

Prefer registering a global pipe via `APP_PIPE` when you need dependency injection.

## Common mistakes

- **Trusting body fields blindly** — Mass assignment / unexpected properties.
- **Validating only in the frontend** — Clients are hostile; server must enforce.
- **Global pipe without transform** — Param/query strings stay strings unexpectedly.
- **Assuming TypeScript types validate runtime JSON** — Types erase at runtime.
