## Why this matters

Public endpoints attract bots and accidental loops. Rate limits preserve availability and reduce credential-stuffing throughput.

<Callout type="mental-model">
  Choose a key (IP, user id, API key), a window, and a limit. Return 429 with clear semantics. Distributed apps need a shared store (often Redis).
</Callout>

## Conceptual throttle policy

Nest's Throttler module implements guard-based limits; tune differently for auth vs read APIs.

```ts
// Conceptual policy object — configure via @nestjs/throttler in app module
export const loginThrottle = {
  name: 'login',
  ttl: 60_000,
  limit: 5,
} as const;
```

## Common mistakes

- **Global identical limits for all routes** — Login needs stricter limits than public GETs.
- **IP-only behind NAT** — May punish whole offices; combine with user keys when authed.
- **Silent drops** — Prefer explicit 429 + Retry-After when appropriate.
