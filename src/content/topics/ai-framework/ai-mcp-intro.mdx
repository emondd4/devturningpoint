<Callout type="mental-model">
MCP standardizes how hosts discover and call external tools/resources. It multiplies capability—so scopes must shrink.
</Callout>

## Why this matters

MCP lets editors and agents talk to databases, browsers, and internal APIs through a shared protocol. Misconfigured servers become privileged backdoors.

## Mental model

- **Host** — Cursor or your agent runtime.
- **Server** — Process exposing tools/resources/prompts.
- **Client session** — Negotiated capabilities.
- **Least privilege** — Mount only needed tools; never whole disks by default.

## Practical checks

- Read the official MCP spec version you target.
- Review each server’s tool list before enabling.
- Prefer read-only servers while learning.
- Log tool invocations when building product agents.

## Interview angle

How does MCP differ from ad-hoc function calling APIs—and what new risks does standardization introduce?
