An agent is a loop with state and tools—not a smarter autocomplete. Reliability comes from bounds, memory design, and interrupts.
</Callout>

## Why this matters

Teams confuse chatbots, tool callers, and agents. Agents persist goals across steps; without budgets they thrash, loop, or cause harm.

## Core pieces

- **State** — What is remembered across steps (typed beats free-form).
- **Planner/policy** — What to do next given state and observations.
- **Tools** — Bounded actions with schemas.
- **Memory** — Short-term transcript vs curated long-term facts.
- **Interrupts** — Human approval before irreversible actions.
- **Eval** — Multi-step scenarios, not single prompts.

## Practical checks

- Max steps and max tokens per run.
- Idempotent tools where possible.
- Distinguish coding agents (IDEs) from product agents (your app).

## Interview angle

When is a single tool call enough—and when do you need a graph with checkpoints?
