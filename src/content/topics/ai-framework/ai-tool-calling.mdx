<Callout type="mental-model">
A tool call is a privileged RPC proposed by a non-deterministic speaker. Validate arguments, authorize, then execute—never the reverse.
</Callout>

## Why this matters

Tools turn tokens into side effects: deploys, emails, DB writes. Without schemas and permissions, “agent demos” become incident reports.

## Pattern

1. Publish a small **allowlist** of tools with JSON schemas.
2. Model proposes `{name, arguments}`.
3. Executor **validates**, **authorizes**, optionally **dry-runs**.
4. Results return as observations; loop with a **max step** budget.
5. Audit every call.

## Practical checks

- Reject unknown tool names.
- Require human confirmation for mutating tools.
- Redact secrets from logs and prompts.

## Interview angle

Contrast unbounded shell tools with least-privilege typed tools.
