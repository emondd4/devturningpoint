## Why this matters

Model and prompt swaps look fine in chat and fail in production. Evaluation freezes inputs and scores outputs so changes are falsifiable.

## Building blocks

1. **Task definition** — Clear success criteria.
2. **Gold / fixture set** — Versioned examples with labels or rubrics.
3. **Metrics** — Exact match, rubric scores, retrieval hit@k, groundedness.
4. **Traces** — Prompt, tools, retrieved docs, latency, cost.
5. **Gates** — Block releases on regressions.

## Practical checks

- Start with 20–50 hard cases, not 10,000 easy ones.
- Split by failure mode (RAG miss vs generation invent).
- Track cost and latency beside quality.

## Interview angle

Describe how you would catch a silent prompt regression in CI.
