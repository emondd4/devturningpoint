## Why release planning

Shipping is a cross-functional event: feature flags, migrations, support scripts, store reviews, and comms.

## Mental model

<Callout type="mental-model">
  Plan by outcomes and risk reduction. Prefer incremental releases. Maintain a launch checklist covering QA signoff, rollback, monitoring, and stakeholder comms.
</Callout>

## Common mistakes

- **Big-bang releases by default**.
- **No rollback story**.
- **Marketing date without eng capacity**.

## Interview angle

<Callout type="interview">
  Design a release plan for a breaking API change with mobile clients.
</Callout>

## Practice checklist

- [ ] Draft a launch checklist.
- [ ] Identify one feature-flaggable slice.
- [ ] Define rollback owners.
