## Why “just one small change” hurts

Untracked changes create surprise scope, broken timelines, and risky hotfixes. Change management separates **product scope change** from **production change**, with clear impact and owners.

## Mental model

<Callout type="mental-model">
  Request → impact (scope/schedule/risk) → decision (accept/defer/reject) → communicate → implement via normal delivery or controlled prod change window.
</Callout>

## Two layers

1. **Backlog/scope change** — New asks enter prioritization; tradeoffs explicit.
2. **Production change** — Deploy/config/data fixes with rollback and comms.

## Common mistakes

- **Verbal yes without replanning** — Hidden debt.
- **Emergency path used for convenience** — Bypasses learning.
- **No stakeholder update after acceptance** — Expectation drift.

## Interview angle

<Callout type="interview">
  Mid-sprint, a VIP asks for a new report. How do you run change control without saying only “no”?
</Callout>

## Practice checklist

- [ ] Write a one-page change request template.
- [ ] Define what qualifies as emergency change.
- [ ] Link change decisions to roadmap/OKR impact.
