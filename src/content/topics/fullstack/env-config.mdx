## Why config is a full-stack concern

Mismatched env vars cause “works on my machine” more than code differences—DB URLs, public vs server Next env, and JWT secrets.

## Mental model

<Callout type="mental-model">
  Separate build-time public config (`NEXT_PUBLIC_*`) from server secrets. Validate env at process boot. Keep `.env.example` complete; never commit secrets.
</Callout>

## Common mistakes

- **Leaking secrets via NEXT_PUBLIC_**.
- **No validation—undefined config at runtime**.
- **One `.env` copied blindly to production**.

## Interview angle

<Callout type="interview">
  Which Nest and Next variables must differ between staging and prod?
</Callout>

## Practice checklist

- [ ] Create `.env.example` for a Next+Nest app.
- [ ] Add boot-time schema validation.
- [ ] Document secret rotation ownership.
