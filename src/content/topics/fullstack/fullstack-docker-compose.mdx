## Why compose for full-stack

Integration bugs appear when services run together. Compose encodes the dependency graph for every developer and CI job.

## Mental model

<Callout type="mental-model">
  One network, named services as DNS, volumes for Postgres data, env files per service. Prefer hot-reload bind mounts in dev; production-like images in CI.
</Callout>

## Minimal service set

`web` (Next), `api` (Nest), `db` (Postgres), `redis`, optional `mail`/`minio` for uploads.

## Common mistakes

- **Hard-coding localhost inside containers** — use service DNS names.
- **No healthchecks** — apps start before DB is ready.
- **Huge images without .dockerignore**.

## Interview angle

<Callout type="interview">
  Design a compose file for Next+Nest+Postgres+Redis with healthchecks.
</Callout>

## Practice checklist

- [ ] Write a compose stack for local DTP-like apps.
- [ ] Use service hostnames in Nest DATABASE_URL.
- [ ] Add a one-command smoke test.
