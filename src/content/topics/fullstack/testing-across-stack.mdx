## Why fullstack testing is a portfolio of bets

One giant E2E suite is slow and brittle. Fullstack teams win by placing **cheap tests close to the code** and a few journey tests at the edges.

## Mental model

<Callout type="mental-model">
  Pyramid by default: many unit/contract tests, fewer API/integration tests, sparse E2E for critical user journeys. Own tests with the code that can break them.
</Callout>

```text
UI components  → unit / component tests
API handlers   → unit + supertest/contract
DB queries     → integration against test DB
Checkout path  → Playwright E2E (staging)
```

## How to divide ownership

- Frontend: components, hooks, a11y smoke.
- Backend: domain logic, authz, API contracts.
- Shared: OpenAPI/contract checks; E2E owned jointly with QA.

## Common mistakes

- **Only E2E** — Slow feedback, flake culture.
- **Mocking the world** — Tests that never catch integration bugs.
- **No test data strategy** — Flakes and collisions in shared envs.

## Interview angle

<Callout type="interview">
  How would you test a NestJS + Next.js checkout without making CI take 40 minutes?
</Callout>

## Practice checklist

- [ ] Map five risks to the cheapest test layer.
