## Why CORS exists

Browsers enforce same-origin policy. CORS is the server’s opt-in for reading cross-origin responses—not an authentication mechanism.

## Mental model

<Callout type="mental-model">
  Simple requests vs preflighted requests. Access-Control-Allow-Origin must be explicit when credentials are used—no `*` with Access-Control-Allow-Credentials.
</Callout>

## Full-stack tip

Prefer same-site deployments (web + API under related hosts) or a BFF to reduce credentialed cross-origin complexity.

## Common mistakes

- **Treating CORS errors as Nest bugs when the browser blocked the response**.
- **Reflecting arbitrary Origin with credentials**.
- **Using CORS as authorization**.

## Interview angle

<Callout type="interview">
  Debug a credentialed fetch from localhost:3000 to api.localhost:4000 that fails CORS.
</Callout>

## Practice checklist

- [ ] Explain when a preflight happens.
- [ ] Configure allowlist origins for staging/prod.
- [ ] Decide BFF vs credentialed CORS for your app.
