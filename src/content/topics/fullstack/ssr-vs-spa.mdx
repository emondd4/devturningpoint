## Why the split matters

Rendering choice affects TTFB, SEO, auth data exposure, and where Nest calls happen.

## Mental model

<Callout type="mental-model">
  Server Components/SSR fetch close to data and ship HTML; client components handle interactivity. Don’t fetch secrets into the client bundle. Prefer server-side Nest calls for privileged data.
</Callout>

## Common mistakes

- **Fetching privileged data in client components**.
- **Making everything client “for convenience”**.
- **Duplicating the same Nest call on server and client without caching strategy**.

## Interview angle

<Callout type="interview">
  When should a dashboard shell be a Server Component with client islands?
</Callout>

## Practice checklist

- [ ] Label three routes as SSR/static/client-heavy.
- [ ] Move one privileged fetch server-side.
- [ ] Measure TTFB before/after a change.
