## Why CSRF still matters

If the browser automatically attaches cookies, a malicious site may trigger state-changing requests. SameSite helps but is not a complete defense.

## Mental model

<Callout type="mental-model">
  Defense in depth: anti-CSRF tokens / Fetch Metadata checks, SameSite cookies, careful CORS credentials, and avoiding cookie auth on cross-site APIs when possible.
</Callout>

## Common mistakes

- **Assuming SameSite=Lax is enough for all cases**.
- **CSRF tokens on safe GETs that mutate**.
- **Disabling security to “fix CORS”**.

## Interview angle

<Callout type="interview">
  Design CSRF protection for a Nest API used by a cookie-authenticated Next app.
</Callout>

## Practice checklist

- [ ] List which endpoints are state-changing.
- [ ] Pick a CSRF strategy and document it.
- [ ] Add a QA negative case for cross-site POST.
