## Why encoding bugs look like “random garbage”

Bangla, emoji, and many European letters need more than one byte. If a system writes UTF-8 and another reads Latin-1, you get **mojibake**—corrupted text that is not a font problem.

## Mental model

<Callout type="mental-model">
  Unicode assigns each character a code point. **UTF-8** is a variable-width encoding of those code points into bytes. Files, sockets, and DBs store bytes; you must agree on the encoding.
</Callout>

## Practical rules

1. Prefer **UTF-8 everywhere** (source files, DB collation strategy, HTTP `charset=utf-8`).
2. JSON text is defined as Unicode; treat payloads as UTF-8 on the wire.
3. Never truncate multi-byte sequences mid-character when slicing strings by byte length.

```js
const text = 'বাংলা';
const bytes = new TextEncoder().encode(text);
console.log(bytes.length); // more than character count
console.log(new TextDecoder('utf-8').decode(bytes));
```

```http
Content-Type: application/json; charset=utf-8
```

## Common mistakes

- Assuming `string.length` equals byte length in every language
- Opening CSV exports in Excel without UTF-8 BOM/awareness
- Mixing Windows-1252 and UTF-8 in legacy DBs
