## Why package managers exist

Copy-pasting libraries does not scale. Package managers resolve **declared** dependencies from a registry, fetch transitive trees, and (with lockfiles) pin exact versions for CI and teammates.

## Mental model

<Callout type="mental-model">
  Manifest (`package.json`, `pubspec.yaml`) = ranges you allow. Lockfile = exact graph that was resolved. CI should install from the lockfile, not re-resolve casually.
</Callout>

## Ecosystem map

| Ecosystem | Manifest | Lockfile | Registry |
| --- | --- | --- | --- |
| JS/TS | package.json | package-lock / pnpm-lock / yarn.lock | npm |
| Dart/Flutter | pubspec.yaml | pubspec.lock | pub.dev |
| Python | pyproject / requirements | poetry.lock / pip freeze | PyPI |

```bash
# npm example
npm ci          # clean install from lockfile (CI-friendly)
npm install lodash
```

```yaml
# pubspec.yaml sketch
dependencies:
  http: ^1.2.0
```

## Common mistakes

- Committing node_modules / build artifacts instead of lockfiles
- Deleting lockfiles “to fix conflicts” without reviewing the new graph
- Trusting every package—supply-chain risk is real; prefer maintained, audited libs
