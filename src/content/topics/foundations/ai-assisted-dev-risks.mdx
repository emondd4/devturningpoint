## Why this belongs in foundations

AI assistants accelerate typing—they do not own production outcomes. Juniors who paste unchecked snippets import **security holes, wrong APIs, and confident nonsense**.

## Mental model

<Callout type="mental-model">
  Treat model output like an untrusted junior PR: useful drafts, mandatory review, tests required, secrets never pasted into prompts from production.
</Callout>

## High-risk failure modes

| Risk | What it looks like | Mitigation |
| --- | --- | --- |
| Hallucinated APIs | Package/method that does not exist | Verify against official docs |
| Insecure defaults | disabled TLS verify, string-built SQL | Security checklist |
| Secret leakage | pasting `.env` into chat | Redact; use local tooling policies |
| License contamination | copying GPL into proprietary code | Know license of suggestions/snippets |
| Silent logic errors | off-by-one, wrong authz | Tests + code review |

## A sane workflow

1. Ask for a design sketch or options, not a giant dump.
2. Integrate in small diffs.
3. Run tests/linters.
4. Cross-check unfamiliar APIs on S1 docs.
5. You remain the author accountable for the change.

<Callout type="danger">
  Never paste production credentials, customer PII, or private keys into third-party AI tools unless your org explicitly allows that tool with proper controls.
</Callout>

## Common mistakes

- **Shipping generated code you cannot explain**
- **Skipping tests because “the model said it’s fine”**
- **Using AI to bypass understanding fundamentals** — interviews and outages will notice

## Interview angle

<Callout type="interview">
  How do you review AI-generated code differently from human-authored code?
</Callout>

## Practice checklist

- [ ] Verify one unfamiliar API from an assistant against official docs.
- [ ] Write a personal “never paste” secrets list.
- [ ] Require a test for any AI-touched business logic change.
