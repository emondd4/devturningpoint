## Why JSON won (for many APIs)

JSON is a text format for objects, arrays, strings, numbers, booleans, and null. It is ubiquitous in HTTP APIs—but easy to misuse with silent `undefined`, number precision, and schema drift.

## Mental model

<Callout type="mental-model">
  Treat JSON as a serialization boundary: validate on the way in, map to domain types inside, and never trust client shapes blindly.
</Callout>

```json
{
  "userId": "u_1",
  "roles": ["editor"],
  "active": true,
  "score": 12.5
}
```

```js
const raw = JSON.parse(text);
if (typeof raw.userId !== 'string') throw new Error('invalid userId');
```

## Sharp edges

- **Numbers** — IEEE floats; money often better as integer minor units.
- **Dates** — no native date type; agree on ISO-8601 strings.
- **Null vs missing** — decide and document.

## Common mistakes

- **Stringifying everything** — loses type checks.
- **Accepting huge unbounded payloads** — DoS via memory.
- **Drifting field names** across clients (`user_id` vs `userId`).

## Interview angle

<Callout type="interview">
  How would you version a JSON field rename without breaking old mobile clients?
</Callout>

## Practice checklist

- [ ] Parse and validate a sample payload in your language.
- [ ] Represent money without floating point.
- [ ] Write a 5-field schema note for one API response.
