## Why practice beats memorizing charts

Interviewers and production reviews ask you to **reason about growth**, not recite a table. This lab trains that muscle on patterns you will see weekly.

## Mental model

<Callout type="mental-model">
  Count how many times the inner work runs as a function of input size n. Then ask whether a better structure (hash set, sorted array, index) changes the dominant term.
</Callout>

## Lab 1 — membership

```js
// Quadratic
function commonNaive(a, b) {
  const out = [];
  for (const x of a) {
    for (const y of b) {
      if (x === y) out.push(x);
    }
  }
  return out;
}

// Average O(|a| + |b|) with a set
function commonSet(a, b) {
  const setB = new Set(b);
  return a.filter((x) => setB.has(x));
}
```

## Lab 2 — “N+1” as complexity

Calling an HTTP endpoint once per row is often worse than a slightly heavier join:

- 100 users × 50ms latency ≈ 5s wall time serial.
- Complexity language: (O(n)) round-trips dominates CPU work.

## Lab 3 — sort then scan

Sorting (O(n \log n)) then a linear scan can beat nested loops for “find pairs” style problems when comparison-based approaches apply.

```js
function hasPairSumSorted(sorted, target) {
  let i = 0, j = sorted.length - 1;
  while (i < j) {
    const s = sorted[i] + sorted[j];
    if (s === target) return true;
    if (s < target) i++;
    else j--;
  }
  return false;
}
```

## Common mistakes

- **Calling everything O(n)** — ignore nested structures and hidden loops in library calls.
- **Ignoring constants that are I/O** — disk and network dwarf CPU for small n.
- **Optimizing the wrong hot path** — measure first when stakes are real.
