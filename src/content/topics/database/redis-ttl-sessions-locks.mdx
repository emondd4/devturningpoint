## Why Redis is more than a cache blob

Sessions need expiry. Rate limits need counters with TTL. Distributed locks need atomic acquire/release. Misusing Redis as a durable source of truth creates silent data loss.

## Mental model

<Callout type="mental-model">
  TTL attaches a lifetime to a key. Sessions store opaque ids → user state with sliding or absolute expiry. Locks typically use `SET key token NX EX seconds` and delete only if the token matches.
</Callout>

```bash
SET session:abc123 '{"userId":42}' EX 3600
SET lock:order:99 "token-xyz" NX EX 30
TTL session:abc123
```

Prefer battle-tested libraries for locks (fencing tokens) when correctness matters; naive locks fail on GC pauses and clock issues.

## Common mistakes

- **No TTL on sessions** — Memory grows forever.
- **Locks without expiry** — Dead owner freezes work.
- **Treating Redis as the only copy of money balances** — Persistence/durability differ from Postgres.

## Interview angle
