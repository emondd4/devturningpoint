## Why this matters

Teams fight religious wars. The practical question is control: ORMs accelerate CRUD; complex sets, window functions, and tuned plans often need SQL you can EXPLAIN.

## Mental model

<Callout type="mental-model">
  ORM = mapping + unit-of-work convenience. SQL = precise set operations. Hybrid is normal: ORM for writes/CRUD, SQL for reports and hot reads.
</Callout>

## How it works

Measure. If the ORM cannot produce a good plan or hides N+1, rewrite that path in SQL. Keep transactions explicit either way.

```sql
-- Hot path: explicit SQL with clear plan
EXPLAIN ANALYZE
SELECT t.id, COUNT(p.id) AS prereq_count
FROM topics t
LEFT JOIN topic_prereqs p ON p.topic_id = t.id
WHERE t.track = 'database'
GROUP BY t.id
ORDER BY prereq_count DESC
LIMIT 20;
```

## Common mistakes

- **All-ORM dogma** — Fighting the ORM for analytics wastes time.
- **String-concat SQL** — Injection risk; use parameters.
- **No EXPLAIN culture** — Guessing indexes fails in production.

## Interview angle

<Callout type="interview">
  Describe a query you would keep in an ORM and one you would write in raw SQL—and why.
</Callout>

## Practice checklist
