## Why this project matters

Shipping a container to a VM is the practical baseline before cloud IaC and Kubernetes.

<Callout type="mental-model">
  Build once in CI, run under a process supervisor, terminate TLS/proxy at the edge.
</Callout>

## Skills this proves

Learning outcomes map to: DEVOPS-DOCKER, DEVOPS-CICD, DEVOPS-NGINX, DEVOPS-SYSTEMD, DEVOPS-LINUX.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

App image → GHCR/Docker Hub → VM pull → systemd unit → Nginx reverse proxy.

Recommended tools: Docker, GitHub Actions, Linux VM, Nginx, systemd.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Dockerfile. 2) Compose local. 3) GH Actions build. 4) VM systemd deploy. 5) Nginx+TLS optional.

## Validation checkpoints

CI builds image; VM serves app via Nginx; restart survives reboot; rollback steps documented.

## Common errors

Running containers as root unnecessarily; secrets in workflow logs; no healthcheck.

## Debugging guidance

journalctl -u; nginx -t; docker logs; curl locally first.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

CI smoke curl after deploy; container healthcheck.

## Security

SSH keys; least ports; non-root container user; secret store for deploy key.

## Performance

Multi-stage builds; layer caching in CI.
