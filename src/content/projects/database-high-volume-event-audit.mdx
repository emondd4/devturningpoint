## Why this project matters

Audit/event tables grow forever. Partitioning and retention are how you stay online.

<Callout type="mental-model">
  Append-only facts; partitions by time; queries must prune; retention is a product decision.
</Callout>

## Skills this proves

Learning outcomes map to: DATABASE-PARTITIONING, DATABASE-JSON, DATABASE-EXPLAIN, DATABASE-BACKUP-REPLICATION, DATABASE-REDIS.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

events(id, ts, actor, action, payload jsonb) partitioned by month; hot/cold query paths; backup/restore drill.

Recommended tools: PostgreSQL, partitioning, optional Redis buffer, pg_partman awareness.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Event model. 2) Partitioning. 3) Ingest load. 4) Investigation queries. 5) Retention+backup drill.

## Validation checkpoints

Inserts prune to partitions; investigation queries time-bounded; drop old partition safely; backup restores sample.

## Common errors

Single huge table; SELECT without time predicate; deleting millions of rows vs detach partition.

## Debugging guidance

EXPLAIN partition pruning; bloat checks; restore dry-run.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Pruning tests; retention script dry-run; restore verification queries.

## Security

Immutable audit policy; restricted delete role; PII minimization in payload.

## Performance

Batch ingest; BRIN/time indexes; Redis buffer optional.
