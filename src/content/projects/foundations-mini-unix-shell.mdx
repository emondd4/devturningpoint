## Why this project matters

Shells sit at the user/kernel boundary—process trees, FDs, permissions, and signals become concrete.

<Callout type="mental-model">
  Parse a line into a process graph, wire FDs, fork/exec, wait, stay responsive.
</Callout>

## Skills this proves

Learning outcomes map to: FOUNDATIONS-PROCESSES, FOUNDATIONS-FILESYSTEMS, FOUNDATIONS-OS-PERMISSIONS, FOUNDATIONS-DEBUGGING.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Lexer/parser → command graph → executor. Builtins in-process; externals via exec. Monitor reads OS process stats.

Recommended tools: C/Rust/Go/Python, Linux or macOS, strace optional.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Single command REPL. 2) Redirection. 3) Pipes. 4) Background jobs. 5) Process monitor. 6) Honest limitation docs.

## Validation checkpoints

Pipelines work; redirection correct; jobs lists background tasks; monitor shows PIDs without crash.

## Common errors

Not restoring FDs; zombies; shelling out instead of execve; busy-loop monitor.

## Debugging guidance

Draw FD graphs; use ps for zombies; log AST for failing lines.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Parse tests; temp-dir integration; skip OS-incompatible cases cleanly.

## Security

Teaching shell only; careful globbing; warn not a login shell.

## Performance

Interval refresh for monitor; avoid tight loops.

## Accessibility

Non-color monitor mode; readable columns.

## Deployment / handoff

Per-OS build notes; document /proc differences.
