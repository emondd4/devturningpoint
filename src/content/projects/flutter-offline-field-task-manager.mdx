## Why this project matters

Field apps fail offline. Employers care about flaky-network design.

<Callout type="mental-model">
  Local DB is source of truth; network is transport; outbox records intent until ACK.
</Callout>

## Architecture / approach

Task + OutboxEntry + SyncCursor. UI reads DB streams; worker drains outbox with backoff.

Recommended tools: Flutter, drift/sqflite, Dio/http, mock API.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Schema/DAOs. 2) Offline CRUD. 3) Outbox worker. 4) Conflicts. 5) Airplane-mode demo.

## Validation checkpoints

Offline create appears immediately and syncs later; conflict path visible; airplane mode usable.

## Common errors

API as source of truth offline; sync loops; heavy JSON on UI isolate.

## Debugging guidance

Log outbox states; simulate 409/500; DevTools timeline.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

DAO tests; fake API outbox drain; offline banner widget test.

## Security

Tokens in secure storage; no PII in logs. Login goes through OAuth2/Keycloak SSO (Authorization Code + PKCE, no client secret in the app); the sensitive record-edit screen is gated behind a biometric re-auth (`local_auth`) with a PIN fallback, on top of — not instead of — the SSO session. See `FLUTTER-MOBILE-SECURITY-IDENTITY`.
