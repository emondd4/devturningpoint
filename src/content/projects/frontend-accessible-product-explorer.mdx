## Why this project matters

Accessible product UIs are legally and ethically expected; they also improve UX for everyone.

<Callout type="mental-model">
  Semantics first, ARIA second. Keyboard parity with pointer. Test with tools and real keyboard.
</Callout>

## Skills this proves

Learning outcomes map to: FRONTEND-HTML-SEMANTICS, FRONTEND-A11Y, FRONTEND-CSS-LAYOUT, FRONTEND-REACT, FRONTEND-REACT-TESTING.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Product list + filters + detail dialog/page. Prefer native controls; document any custom widgets with ARIA patterns.

Recommended tools: React or Next.js, TypeScript, Testing Library, axe-core.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Semantic layout. 2) Filterable list. 3) Detail view. 4) Keyboard + focus. 5) axe/Testing Library checks.

## Validation checkpoints

Tab order sensible; filters usable by keyboard; axe critical issues zero on main flows.

## Common errors

Div buttons; focus traps broken; color-only status; uncontrolled list keys.

## Debugging guidance

Keyboard-only walkthrough; axe + screen reader spot checks; React Testing Library queries by role.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

RTL tests for filter and dialog; axe in CI optional.

## Security

Escape product HTML; CSP basics if Next.

## Performance

Virtualize if large lists; avoid layout thrash on filter.

## Accessibility

Primary focus of this project—WCAG AA targets for contrast, names, and keyboard.

## Deployment / handoff

Static/Vercel-style deploy optional; document a11y statement.

Capture every item in frontmatter `portfolioEvidence`. Artifacts beat claims.
