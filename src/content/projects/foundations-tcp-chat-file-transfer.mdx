## Why this project matters

HTTP hides framing. Raw TCP forces you to own buffering, message boundaries, and partial reads.

<Callout type="mental-model">
  TCP is a byte stream. You invent framing. Partial reads are normal. Integrity is your job.
</Callout>

## Skills this proves

Learning outcomes map to: FOUNDATIONS-TCP-IP, FOUNDATIONS-PROCESSES, FOUNDATIONS-DEBUGGING, FOUNDATIONS-SECURITY-BASICS.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Binary header (type/length/checksum). Separate IO from app logic. Stream file chunks with final hash.

Recommended tools: Python asyncio or Node net, tcpdump optional, Git.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) PROTOCOL.md. 2) Framing tests. 3) Chat broadcast. 4) File transfer. 5) Disconnect chaos tests.

## Validation checkpoints

Two clients chat; 10MB+ file matches checksum; client kill does not crash server.

## Common errors

One recv = one message; deadlocks; path traversal on filenames; unbounded frames.

## Debugging guidance

Log headers; hex dump first bytes; fuzz split buffers.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Codec unit tests with split buffers; integration on ephemeral ports.

## Security

Localhost default; sanitize names; cap frame size; document no TLS yet.

## Performance

Buffered writes; measure large-file throughput.
