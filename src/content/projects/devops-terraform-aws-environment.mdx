## Why this project matters

ClickOps does not scale. Terraform makes environments reviewable, repeatable, and destroyable.

<Callout type="mental-model">
  Desired state in Git. State file is sacred. IAM is blast radius control.
</Callout>

## Skills this proves

Learning outcomes map to: DEVOPS-TERRAFORM, DEVOPS-AWS, DEVOPS-IAM, DEVOPS-NETWORKING, DEVOPS-SECRETS.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

VPC + subnets + security groups + small compute (EC2/ECS/lightsail-like choice) + remote state backend. Modules for network and app.

Recommended tools: Terraform, AWS free tier/sandbox, S3+DynamoDB state, tflint optional.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Backend state. 2) Network module. 3) Compute+SG. 4) IAM roles. 5) Apply/destroy + docs.

## Validation checkpoints

terraform plan clean; apply idempotent; destroy works; IAM least privilege explained.

## Common errors

State in Git; admin IAM for app; hardcoding AZs without data sources.

## Debugging guidance

Plan diffs; state list; AWS console cross-check carefully.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>
