## Why this project matters

Modern QA owns the signal that protects releases—pipelines, not only cases.

<Callout type="mental-model">
  Multiple quality signals → policy → release decision. Fast feedback on PRs; deeper on main.
</Callout>

## Skills this proves

Learning outcomes map to: QA-CI-INTEGRATION, QA-PERFORMANCE, QA-PLAYWRIGHT, QA-API-TESTING, QA-STLC.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

CI workflows: unit+API on PR; E2E smoke; nightly full; a11y/perf smoke; publish report; risk rubric.

Recommended tools: GitHub Actions, Playwright, k6 or Lighthouse CI, axe, Allure/Reportportal optional.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Map signals. 2) Wire PR gates. 3) Nightly suite. 4) a11y/perf. 5) Go/no-go template.

## Validation checkpoints

PR blocked on critical fails; reports published; rubric applied on a sample release.

## Common errors

All tests on every PR; flaky gates ignored; vanity metrics without thresholds.

## Debugging guidance

Failed job bisect; flake quarantine; compare baselines.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Pipeline itself tested via intentional failing PR.

## Security

Secret hygiene; dependency scanning awareness; DAST light optional.

## Performance

Budgets with baselines; fail on regressions beyond threshold.

## Accessibility
