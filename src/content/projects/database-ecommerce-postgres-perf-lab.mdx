## Why this project matters

Slow checkouts and catalogs are usually query/index problems. Tuning with evidence is a core DBA/backend skill.

<Callout type="mental-model">
  Measure → hypothesize → index/rewrite → re-measure. Indexes are not free.
</Callout>

## Skills this proves

Learning outcomes map to: DATABASE-POSTGRES-INDEXING, DATABASE-EXPLAIN, DATABASE-INDEX-ANTIPATTERNS, DATABASE-CTES, DATABASE-LOCKING.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Products, variants, carts, orders, order_items at moderate scale (100k+ rows). Lab scripts for hot queries.

Recommended tools: PostgreSQL, pgbench or custom load, EXPLAIN (ANALYZE, BUFFERS).

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Schema+seed scale. 2) Baseline EXPLAIN. 3) Indexes/rewrites. 4) Write-path impact. 5) Report.

## Validation checkpoints

Documented p95 improvement; plans show index usage; write overhead noted.

## Common errors

Indexing everything; ignoring write cost; trusting EXPLAIN without ANALYZE.

## Debugging guidance

EXPLAIN (ANALYZE, BUFFERS); track seq scans; vacuum/analyze awareness.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>
