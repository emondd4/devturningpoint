## Why this project matters

Collaborative boards expose concurrency, ordering, and accessibility of complex widgets.

<Callout type="mental-model">
  Optimistic intent → ack/nack → reconcile. Presence is ephemeral; board state is durable.
</Callout>

## Skills this proves

Learning outcomes map to: FRONTEND-REACT, FRONTEND-PERFORMANCE, FRONTEND-REACT-TESTING, FRONTEND-A11Y, FRONTEND-NEXTJS.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Board columns/cards; WS events; optimistic moves with rollback; keyboard alternative to drag-drop.

Recommended tools: Next.js, WebSocket/SSE stub, TanStack Query, dnd library with a11y.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Board CRUD. 2) DnD + keyboard moves. 3) WS sync. 4) Conflicts. 5) Perf+a11y hardening.

## Validation checkpoints

Two browsers stay consistent; conflict visible; keyboard can move cards; 500 cards usable.

## Common errors

Key instability; uncontrolled optimistic races; DnD-only interaction.

## Debugging guidance

Event log panel; React profiler; multi-client scripted moves.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Reducer/reconciliation unit tests; a11y keyboard move tests.

## Security

Authz on mutations; validate event payloads; XSS in issue bodies.

## Performance

Windowing; avoid re-rendering whole board per event.

## Accessibility

Keyboard reordering; live regions for moves; non-pointer path required.

## Deployment / handoff

Compose with WS stub; document scaling limits.

## Portfolio evidence checklist

Capture every item in frontmatter `portfolioEvidence`. Artifacts beat claims.
