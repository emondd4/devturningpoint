## Why this project matters

Document extraction is where LLMs meet schemas. Reliability comes from validation, metrics, and human review.

## Market / role relevance

Observed in Bangladesh job listings reviewed for software roles: AI feature delivery and AI-assisted engineering appear as plus skills, while verification, security judgment, and measurable quality remain baseline expectations.

## What job skills it proves

Structured outputs, fail-closed parsing, field-level eval, and review workflows.

## Prerequisites

Structured outputs and prompt engineering topics recommended.

## Architecture / approach

Document text → LLM extract → schema validate → confidence gate → human review → accepted record.

## Recommended tools

Local Ollama preferred; Zod/Pydantic for validation.

## Setup

1. Prefer synthetic invoices/resumes.
2. Install local model runtime.
3. Cap any cloud spend before first call.

## Step-by-step guidance

Milestones M01–M04. Keep the schema small (8–15 fields).

## Evaluation / security / cost / latency notes

**Eval:** field P/R.
**Security:** treat document text as untrusted (prompt injection).
**Cost/latency:** batch carefully; cache embeddings only if you add them later.

## Portfolio evidence

Save every item listed in frontmatter `portfolioEvidence`. Include eval scores, cost/latency notes, and security checklist outcomes.

## Stretch goals

Add OCR for scanned PDFs and measure OCR-induced error separately.

## Retrospective

Which fields hallucinated most? Did confidence correlate with true errors?
