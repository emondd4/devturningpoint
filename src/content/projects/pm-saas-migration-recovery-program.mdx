<Callout type="warning" title="Simulated vs real evidence">
  Practice artifacts are fine when labeled simulated. Never claim fabricated approvals, budgets, or outcomes as real results.
</Callout>

## Why this project matters

Recovering troubled programs is where PM seniority is tested—truth, tradeoffs, and credible plans.

<Callout type="mental-model">
  Diagnose reality → re-baseline options → decide tradeoffs → communicate risks → execute recovery increments.
</Callout>

## Skills this proves

Learning outcomes map to: PM-RISK, PM-STAKEHOLDERS, PM-SCRUM, PM-ESTIMATION, PM-SDLC.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Use a simulated troubled SaaS migration scenario (legacy→new). Produce assessment, options, chosen recovery plan, RAID, and exec comms—all labeled simulated.

Recommended tools: RAID log, Decision log, Program plan, Executive brief template.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Situation assessment. 2) Options+tradeoffs. 3) Re-baseline plan. 4) RAID+comms. 5) First 30-day recovery increments.

## Validation checkpoints

Options include cuts; risks quantified qualitatively; exec brief honest; no fake approvals presented as real.

## Common errors

Hero timelines; hiding bad news; scope unchanged with magical productivity.

## Debugging guidance

If plan still impossible, cut scope or extend time—document the decision.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

Pre-mortem; stakeholder Q&A rehearsal notes.
