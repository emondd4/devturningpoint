## Why this project matters

Checkout is conversion-critical and state-heavy—perfect for systems and a11y rigor.

<Callout type="mental-model">
  Tokens → components → flow. Every component needs states. Handoff is a product.
</Callout>

## Skills this proves

Learning outcomes map to: UIUX-DESIGN-SYSTEMS, UIUX-PROTOTYPING, UIUX-A11Y, UIUX-COLOR, UIUX-FIGMA.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Foundations (type/color/space) → primitives → checkout pattern pages → prototype → handoff.

Recommended tools: Figma variables/tokens, Prototype, A11y plugins, Handoff specs.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Token foundations. 2) Form components+states. 3) Checkout flow. 4) Prototype. 5) Handoff+a11y audit.

## Validation checkpoints

Components cover default/hover/focus/disabled/error; contrast AA; handoff lists spacing/tokens.

## Common errors

Pretty screens without states; one-off colors; handoff as flattened screenshots only.

## Debugging guidance

If engineers ask basic questions, strengthen tokens and specs.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Prototype task test; contrast checks; content review.

## Security

Privacy microcopy for payments; no real card data in prototypes.

## Performance

Reduce checkout steps/cognitive load; progressive disclosure.

## Accessibility

Focus order in prototype notes; error association; contrast.

## Deployment / handoff

Figma library + published case study.
