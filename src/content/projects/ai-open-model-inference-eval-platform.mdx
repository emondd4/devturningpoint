## Why this project matters

Open models need the same discipline as cloud APIs: serving, eval gates, SLOs, and security.

## Market / role relevance

Observed in Bangladesh job listings reviewed for software roles: AI feature delivery and AI-assisted engineering appear as plus skills, while verification, security judgment, and measurable quality remain baseline expectations.

## What job skills it proves

Local serving, dataset versioning, regression gates, latency SLOs, endpoint hardening.

## Prerequisites

Evaluation basics and LLM fundamentals; willingness to run local models.

## Architecture / approach

Client → inference API → model runtime → eval harness → metrics/report store → release gate.

## Recommended tools

Ollama (or similar), harness scripts, SQLite for run history.

## Setup

1. Confirm machine can run a small open model.
2. Prefer fully local for this project.
3. If comparing to a paid API, cap spend first.

## Step-by-step guidance

Milestones M01–M04. Plant a regression once to prove the gate.

## Evaluation / security / cost / latency notes

**Eval:** regression vs baseline.
**Security:** authz, rate limits, hostile prompts.
**Cost/latency:** p50/p95 and energy/cloud cost notes.

## Portfolio evidence

Save every item listed in frontmatter `portfolioEvidence`. Include eval scores, cost/latency notes, and security checklist outcomes.

## Stretch goals

Add canary traffic split between two model versions.

## Retrospective

What SLO was hardest to meet locally? When would you still choose a hosted API?
