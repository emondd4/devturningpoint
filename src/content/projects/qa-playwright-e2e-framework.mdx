## Why this project matters

Fragile E2E suites destroy trust. Framework design is the difference between help and noise.

<Callout type="mental-model">
  Few high-value journeys. Isolated data. Traces on failure. Quarantine with ownership.
</Callout>

## Skills this proves

Learning outcomes map to: QA-PLAYWRIGHT, QA-CI-INTEGRATION, QA-API-TESTING, QA-TEST-DESIGN, QA-BUG-REPORTING.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Playwright TS project; fixtures for auth/data; page objects/helpers; CI shards; artifact upload.

Recommended tools: Playwright, TypeScript, GitHub Actions, Trace viewer.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Scaffold. 2) First journey. 3) Fixtures/data. 4) CI+traces. 5) Flake playbook.

## Validation checkpoints

CI fails on real bugs; traces available; flake rate tracked; selectors role-based where possible.

## Common errors

Sleeps everywhere; shared mutable users; huge suite of low-value tests.

## Debugging guidance

Trace viewer; headed mode; network logs; bisect flakes.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Meta: lint; seed isolation tests; a11y smoke optional.

## Security

Secrets in CI secrets; no prod credentials; sanitize artifacts.

## Performance

Parallel wisely; avoid unnecessary browser startups.

## Accessibility

Optional axe checks on critical pages.

## Deployment / handoff

CI is the deployment of tests.
