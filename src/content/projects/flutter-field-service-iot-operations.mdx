## Why this project matters

Industrial/mobile ops apps need jank control, native bridges, and reliability.

<Callout type="mental-model">
  UI observes domain state; telemetry ingest isolated; native behind narrow ports.
</Callout>

## Skills this proves

Learning outcomes map to: MOBILE-FLUTTER-PLATFORM, MOBILE-FLUTTER-PERFORMANCE, MOBILE-FLUTTER-STATE, MOBILE-FLUTTER-DEPLOYMENT, MOBILE-FLUTTER-TESTING.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Modules: work orders, devices, telemetry, sync, diagnostics. Fake device gateway; one real platform channel.

Recommended tools: Flutter, platform channels, WebSocket stub, DevTools.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Architecture. 2) Work orders. 3) Telemetry isolate. 4) Platform channel. 5) Perf+release notes.

## Validation checkpoints

Telemetry UI responsive under burst; channel works; work orders offline-tolerant.

## Common errors

Parse telemetry on UI isolate; fat channel APIs; god services.

## Debugging guidance

Timeline jank; channel error logs; websocket chaos.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Channel contract fakes; isolate unit tests; optional goldens.

## Security

Validate payloads; secure storage; least privilege native APIs.

## Performance

Budget cold start, scroll, charts; document numbers.

## Accessibility

Alerts not color-only; scalable text for field glare.
