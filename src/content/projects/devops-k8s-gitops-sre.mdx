## Why this project matters

Platforms fail operationally, not only at kubectl apply. GitOps+SLO is how teams stay sane.

<Callout type="mental-model">
  Git is desired state. Controllers reconcile. SLOs decide when to slow feature work.
</Callout>

## Skills this proves

Learning outcomes map to: DEVOPS-KUBERNETES, DEVOPS-OBSERVABILITY, DEVOPS-SLO, DEVOPS-HELM, DEVOPS-INCIDENT.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

App Helm chart; GitOps app-of-apps; Prometheus metrics; Grafana dashboard; error budget policy doc.

Recommended tools: kind/k3d/EKS, Helm, Argo CD or Flux, Prometheus/Grafana, GitHub.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Cluster+workload. 2) Helm package. 3) GitOps. 4) Metrics/SLO. 5) GameDay incident.

## Validation checkpoints

Git change rolls out; bad deploy auto/manual revert path; SLO dashboard live; postmortem written.

## Common errors

kubectl-only snowflakes; no resource requests; SLO on vanity metrics.

## Debugging guidance

kubectl describe/events; Prometheus queries; GitOps sync status.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>
