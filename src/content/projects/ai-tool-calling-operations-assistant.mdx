## Why this project matters

Tool calling turns text into side effects. Permission design and auditability are the product.

## Market / role relevance

Observed in Bangladesh job listings reviewed for software roles: AI feature delivery and AI-assisted engineering appear as plus skills, while verification, security judgment, and measurable quality remain baseline expectations.

## What job skills it proves

Schema-first tools, dry-run, allowlists, audit logs, and agent step bounds.

## Prerequisites

Tool calling and AI security topics recommended.

## Architecture / approach

User request → model proposes tool calls → schema validate → dry-run/confirm → execute → observe → answer.

## Recommended tools

Provider tool APIs or local models with tool support; mock status/incident APIs.

## Setup

1. Build mock ops backends (status, restart flag, deploy note).
2. Default dry-run=true.
3. Cap API spend.

## Step-by-step guidance

Milestones M01–M04. Prefer fewer, sharper tools over a kitchen sink.

## Evaluation / security / cost / latency notes

**Eval:** scenario success + blocked unsafe calls.
**Security:** least privilege, confirmations, redaction.
**Cost/latency:** tool loops multiply tokens—budget max steps.

## Portfolio evidence

Save every item listed in frontmatter `portfolioEvidence`. Include eval scores, cost/latency notes, and security checklist outcomes.

## Stretch goals

Expose one tool via MCP and compare UX to direct function calling.

## Retrospective

Which prompt almost caused a destructive call? What rule would you add?
