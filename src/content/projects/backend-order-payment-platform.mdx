## Why this project matters

Payments punish naive retries. Idempotency and durable workflows are senior backend signals.

<Callout type="mental-model">
  Clients retry. Webhooks duplicate. Your invariants must survive both.
</Callout>

## Skills this proves

Learning outcomes map to: BACKEND-QUEUES, BACKEND-REDIS, BACKEND-LOGGING, BACKEND-TESTING, BACKEND-SECURITY.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Orders → payment intents → webhook inbox → outbox to fulfillment queue. Idempotency keys on write APIs. DB transactions guard state transitions.

Recommended tools: NestJS, Postgres, Redis/Bull, Stripe test mode or fake PSP, OpenTelemetry optional.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Order model+states. 2) Idempotent pay intent. 3) Webhook inbox. 4) Outbox/queue worker. 5) Chaos duplicates.

## Validation checkpoints

Duplicate pay requests do not double-charge; webhook replays safe; order state machine forbids illegal transitions.

## Common errors

Non-idempotent charge endpoints; processing webhooks before verify; queue side effects outside tx/outbox.

## Debugging guidance

Trace ids across HTTP→DB→queue; replay fixtures.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification
