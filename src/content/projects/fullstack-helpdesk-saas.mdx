## Why this project matters

Helpdesk workflows mirror real SaaS: roles, SLA-ish states, notifications, and browser security.

<Callout type="mental-model">
  Agents and customers see different worlds. Mutations must be CSRF-safe. Notifications are async.
</Callout>

## Skills this proves

Learning outcomes map to: FULLSTACK-CORS-CSRF, FULLSTACK-AUTH-FLOWS, FULLSTACK-E2E-TESTING, FULLSTACK-SSR-BOUNDARIES, BACKEND-QUEUES.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Tickets+comments+assignments. Agent/customer roles. Optional email queue stub. Realtime optional via SSE.

Recommended tools: Next.js, NestJS, Postgres, Redis optional, Playwright.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Roles. 2) Ticket lifecycle. 3) Comments. 4) Notifications stub. 5) E2E critical paths.

## Validation checkpoints

Customer cannot access others' tickets; agent can assign; CSRF protected mutations; E2E green.

## Common errors

CORS * with credentials; missing CSRF on cookie auth; notification send in request thread only.

## Debugging guidance

Dual-role browser profiles; trace ticket id across services.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Playwright customer vs agent journeys; API authz tests.

## Security

CSRF/CORS checklist; XSS in markdown comments; rate limit login.

## Performance

Index ticket filters; paginate comment threads.

## Accessibility

Ticket forms and status announcements.

## Deployment / handoff

Compose + seed roles; staging notes.
