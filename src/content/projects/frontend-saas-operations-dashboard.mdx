## Why this project matters

Dashboards are where product teams live—fetching, authz, and dense UI correctness matter more than animations.

<Callout type="mental-model">
  Server state ≠ UI state. Cache keys encode inputs. Failures are first-class UI.
</Callout>

## Skills this proves

Learning outcomes map to: FRONTEND-REACT, FRONTEND-NEXTJS, FRONTEND-PERFORMANCE, FRONTEND-REACT-TESTING, FRONTEND-A11Y.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

App router pages for overview, entities, detail. TanStack Query for server data; MSW for local demos; role-aware nav.

Recommended tools: Next.js, TypeScript, TanStack Query, Recharts or similar, MSW.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) App shell+auth stub. 2) Query data layer. 3) Tables/charts. 4) Error/empty/retry. 5) Tests+perf pass.

## Validation checkpoints

Retry works; stale data rules documented; unauthorized routes guarded; main interactions keyboardable.

## Common errors

Fetching in render loops; cache key collisions; blocking SSR with client-only assumptions blindly.

## Debugging guidance

React Query devtools; network throttling; render profiling.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

MSW integration tests for table filters; component tests for error banners.

## Security

XSS-safe rendering; no tokens in localStorage without justification; CSRF awareness if cookies.

## Performance

Measure LCP/INP on dashboard; paginate tables; memoize heavy charts carefully.

## Accessibility

Tables with headers; chart non-color encodings; focusable controls.

## Deployment / handoff

Preview deploy + env example without secrets.
