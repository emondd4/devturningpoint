## Why this project matters

Expense trackers exercise CRUD UI, validation, and persistence—core junior Flutter skills.

<Callout type="mental-model">
  UI widgets vs repository owning persistence; rebuild only what changed.
</Callout>

## Skills this proves

Learning outcomes map to: MOBILE-FLUTTER-WIDGETS, MOBILE-FLUTTER-STATE, MOBILE-FLUTTER-FORMS, MOBILE-FLUTTER-STORAGE, MOBILE-FLUTTER-NAVIGATION.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Screens: list, add/edit, category summary. Small state layer + local repository; seed demo data.

Recommended tools: Flutter SDK, shared_preferences or drift/sqflite, VS Code/Android Studio.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) Shell+theme. 2) Model+repo. 3) Forms. 4) List/filters. 5) Totals. 6) Tests.

## Validation checkpoints

Expense survives restart; invalid amount blocked; totals match fixtures; empty state intentional.

## Common errors

Full-tree rebuilds; money as naive doubles without policy; form key mistakes.

## Debugging guidance

DevTools rebuild overlays; log repository IO; fixed seed DB.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

Unit totals; widget validation; optional golden list tile.

## Security

Local-only scope; avoid logging PII if exporting.

## Performance

ListView.builder; no huge sync loads on UI isolate.

## Accessibility

Semantic labels; contrast; large tap targets.
