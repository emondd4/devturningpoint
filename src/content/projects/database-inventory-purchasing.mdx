## Why this project matters

Inventory/purchasing systems live or die by constraints and clear relational modeling.

<Callout type="mental-model">
  Entities and relationships first; constraints encode rules; queries prove the model useful.
</Callout>

## Skills this proves

Learning outcomes map to: DATABASE-RELATIONAL, DATABASE-SQL, DATABASE-JOINS, DATABASE-TRANSACTIONS, DATABASE-POSTGRES-TYPES.

## Prerequisites

Complete related topics first. If starting early, expect to backfill fundamentals under load.

## Architecture / approach

Suppliers, products, warehouses, POs, receipts, stock levels. Enforce non-negative stock via constraints/triggers carefully documented.

Recommended tools: PostgreSQL, dbdiagram/DBeaver,  ent migrations or SQL files.

## Step-by-step guidance

Work one milestone at a time. Restate the objective, implement the smallest vertical slice, run the validation checklist, then capture portfolio evidence before continuing.

1) ERD. 2) DDL+constraints. 3) Seeds. 4) Receiving transaction. 5) Reports.

## Validation checkpoints

Invalid FKs rejected; receiving updates stock atomically; reports match hand calculations.

## Common errors

Spreadsheet tables; nullable FKs everywhere; calculating stock only in app.

## Debugging guidance

Explain constraints failures; transaction rollback tests.

<Callout type="tip" title="Hypothesis-driven debugging">
  One hypothesis → one falsifying check → update notes. Avoid blind retries.
</Callout>

## Tests / verification

SQL tests for invariants; transaction scenarios.

## Security

Least-privilege DB roles for app vs admin; no prod data in seeds.

## Performance

Index FK/join columns used in reports.
